# v0.4 第五步：排版设置与开发包交付

本步完成冻结计划中的排版偏好、系统主题、统一回归和 Windows 开发包。package、Cargo、Cargo.lock、Tauri、界面及 SBOM 统一为 0.4.0。仅借鉴 MarkText 的交互设计，没有导入其代码或资源。

## 外观与持久化

EM → 设置新增正文行高（1.2–2.2，步长 0.1）、最大内容宽度（自适应、720/900/1080 px）、代码字号（10–22 px）和代码换行；正文字号支持 12–24 px。源码、即时渲染、分屏预览与阅读模式应用同一组偏好，各面板内限制内容宽度并居中。

关闭代码换行时，源码中每条代码逻辑行独立横向滚动，渲染代码按整块横向滚动；普通正文继续换行。源码代码装饰只检查可见语法范围，超长单行继续沿用源码高亮暂停策略。外观变化不写入 Markdown、不消耗正文撤销记录，也不改变 HTML、DOCX 或系统打印的交付样式。

跟随系统主题默认关闭；开启后分别记忆系统浅色、深色对应的四主题之一，系统变化实时应用。关闭后恢复手动配色。固定格式栏和选区浮动栏可分别开关。

外观使用版本化的 `easym-appearance` 记录，兼容旧主题、字号及工具栏记录。每个字段独立验证，损坏 JSON/未知版本回退旧设置，越界字段回退有效值。首次加载不覆盖已有记录，保存失败提示并保留当前会话外观。恢复默认外观只处理这一组偏好，保留正文、草稿、历史、历史目录和导引记录。

## 性能修复与验收

第五步验收发现此前工具栏每次输入都调用完整 AST 表格映射，5 MiB 文档输入 P95 达到 4691.8 ms。表格和段落工具状态现改用 CodeMirror 已有增量语法树，实际命令仍以共享 Markdown AST 严格确认结构、范围及 revision，不能绕过源映射校验。新增测试验证顶层/嵌套表格、代码结构和大文档状态查询无需序列化正文。

性能脚本保留 5 MiB、100 KiB 单行、100 图片和 20 MiB 图片字节边界，增加 2,000 单元格/20 列及 200 行正文表格的打开与末尾单元格选择、选区浮层定位及滚动隐藏测量。输入 P95 超过冻结的 50 ms 目标会明确失败。浮层测量单独记录 160 ms 有意去抖与自动操作耗时，不能混作输入下一帧延迟。

新增 `pnpm verify:appearance` 纳入完整回归与 CI，验证旧设置迁移、字体/行高/宽度/换行、源码/即时/分屏/阅读、系统浅深切换及记忆、重启、恢复默认、存储失败、四主题和窄窗口。通过 HTML 字节、DOCX 正文及样式 XML、打印 DOM/计算样式比较，确认编辑外观不影响导出。

本机完成前端 42 文件 / 231 项单测、Windows Rust 57 项测试、类型检查/生产构建、版本一致性及第三方许可核验（430 个依赖、234 份许可文本、0 缺项）。完整回归 21/21 组通过；查找/模板各 6 倍 CPU 降速通过。Microsoft Word `16.0.20430.20146` 的五个当前导出样例打开、分页、编辑保存及再打开通过。

本机 Windows `10.0.26200`、Core 5 220H、31.7 GiB、Chromium `156.0.8078.4`，最终性能如下；打开/表格操作耗时包含自动化交互。

## 剩余验收

第五步随本次提交交付，并按用户指示推送 feature/v0.4；main 合并仍另行处理。当前源码的三平台 CI 和 Windows 隔离安装/卸载需要推送后运行；日常电脑不执行替换安装/注册表的 CI 验收脚本。

Windows 真实中文 IME 候选、组合删除和 Tab，跨块拖选、原生文件/导出对话框、系统 PDF 保存/取消、原生历史与批图操作和重启，需要实机验证。合成 composition、IPC fixture、Chromium 打印样式及原生启动检查各有范围，不能替代这些操作。

macOS/Linux 原生 GUI、读屏、WPS/LibreOffice、macOS 许可文本/SDK 复核和正式签名/公证仍保留既有缺口。当前产物为未签名开发包，需要 WebView2 Runtime，不标记为正式发行。v0.4 冻结的五步实现至此收尾，下一阶段范围另行冻结。
