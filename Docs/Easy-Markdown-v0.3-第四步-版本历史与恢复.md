## 使用流程

1. 在桌面版打开已保存的 Markdown，通过 EM 菜单进入“版本历史”。首次访问仅查询，不保存正文、不默认启用；确认启用后归档磁盘基线。未保存文档和浏览器显示能力说明，原有浏览器草稿恢复继续保留。
2. 点击“创建快照”保存当前内存编辑与相关图片，不触发正文保存；可命名、固定版本。已启用文件首次保存前保留磁盘版本，成功普通保存创建去重、至少间隔 60 秒的自动版本。固定状态与名称可修改，不改不可变归档内容。
3. 选择版本，后台计算逐行差异，分别显示归档/当前全文、编码与换行、图片引用/字节/实例参数变化，以及最多 12 张归档缩略图。差异取消或超限后仍可查看全文。
4. 查看差异后点击恢复并明确确认。先检查外部 revision、保留当前内存的恢复前快照，再提交目标正文、重定位图片与元数据；编辑器只有一个撤销项。恢复后正文已经保存，撤销产生未保存编辑，重做复用已落盘资源。
5. “另存完整副本”保留归档正文的实际字节及原相对图片引用；另存目标不能是已打开文档，原路径图片存在不同字节时拒绝覆盖，请选择另一目录。目标不完整时可以明确选择仅另存正文，并检查缺图。
6. 配额或自动保留规则达到限制后，使用清理预览检查候选，确认才删除。固定版本需先取消固定才能手动选择删除。

面板锁定目标编辑、标签切换、关闭、资源操作和自动保存；组合输入期间不启动。Tab/Shift+Tab 循环焦点，Esc 关闭并返回 EM；原生修改提交期间禁用退出，不能虚报取消已派发的写入。四种主题沿用现有配色，没有新增常驻工具栏。

## 数据与身份

```text
.easym/history/
  index.json
  documents/<document UUID>/snapshots/<snapshot UUID>.json
  documents/<document UUID>/restore-<operation UUID>.json
  objects/<SHA-256 hex>
```

历史 schema 1 独立于图片元数据 schema。索引保存同目录文件名与持久 UUID 的映射、启用状态、配额、名称/固定注解和删除墓碑；清单记录身份、父版本、时间、原因、正文对象/字节格式/base revision、资源对象和图片 recipe。

进程 fileId 仅作文件授权，不能作为持久历史身份。重启不混用身份；同内容不同文件不会自动合并。另存为新目标保留独立历史，覆盖已有目标时把其旧历史留作孤立映射；另存到当前路径不会拆分身份。同目录重命名后可明确重新关联已不存在的原路径，跨目录不会猜测关联。

归档包含真实正文 BOM/CRLF 字节、本地授权 PNG/JPEG、已知实例的原始/显示副本和 recipe。对象按 SHA-256 去重，每次读取复核哈希；图片同时检查格式、尺寸与 sourceHash。越界/绝对路径等不授权引用记录在可选 `unarchivedReferences`，其默认空值兼容既有 schema 1，存在这些引用或缺图的快照标为不完整。HTTP(S) 只保留原链接，不主动抓取，完整性只针对可归档本地资源，不承诺远程图离线可用。

所有操作在现有 Storage 原生写入队列中串行；文件与目录拒绝路径越界和符号链接。未知历史 schema 只读保留，未知/损坏图片元数据不能静默丢弃 recipe 并生成“完整”基线。

## 事务与失败

- 创建顺序为不可变对象 → 原子清单 → 原子索引。查询核对已完成清单，可恢复中断的索引关联；只有孤立对象时不冒充完整快照。缺失索引但存在历史数据时停止并保留，避免重建错误身份。
- 启用和首次保存前核对编辑器基准 revision，避免用过期引用清单归档外部新正文。普通保存历史失败仍返回已保存正文，明确提示快照未完成。
- 长正文引用分析使用后台 Worker，10 秒超时后释放任务。普通保存可跳过失败的历史分析继续提交正文，并发出警告；手动快照或启用失败会停止该历史操作。
- 完整恢复必须校验目标正文、所有目标图片与 recipe；目标缺图、哈希损坏、未知 schema、混合换行或外部冲突阻止提交。恢复前快照创建失败也阻止提交。
- 原图片被删除时，完整目标可从对象库重新生成不可变的 hash 命名副本；已有同路径不同字节使用新路径，不覆盖。恢复前当前正文仍归档，其缺图状态会提示，不能因当前缺图阻止恢复完整旧版本。
- AST 仅修改图片 URL 与对应引用定义，保持说明、标题、普通文字和代码。无法安全重定位时停止，允许另存原字节副本。恢复沿用当前 UTF-8/BOM、LF/CRLF；精确归档字节使用副本。
- 正文沿用已有资源保存事务。恢复日志记录候选、恢复前版本、预期/实际提交哈希及后处理状态；正文提交后出错报告已恢复、后处理待修复。重启仅在磁盘仍匹配拟提交哈希时补历史记录，从不重写后来外部编辑。
- 副本预检所有资源碰撞后再写不可变图片，正文最后提交。正文写入前失败可能留下未引用的新图片文件，但不覆盖旧图片、原正文或打开文档，不声称回滚了已经落盘的资源。

## 限制、保留与清理

| 项目 | 实现限制 |
| --- | --- |
| 单正文 / 单 JSON | 10 MiB / 4 MiB |
| 单图片 / 一次资源字节 | 20 MiB / 128 MiB |
| 图片尺寸 | 单边 8192，最多 2400 万像素 |
| 文档映射 / 单快照资源与实例 | 4096 / 各 4096 |
| 目录快照扫描 / 对象清理扫描 | 10000 / 40000 |
| 默认目录预算 / 可配置 | 512 MiB / 1–4096 MiB |
| 差异输入 | 每侧 5 MiB、100000 行 |
| 差异计算 | 10 秒 Worker 超时，内部 9.5 秒与 200 万 trace 单元上限 |
| 差异界面 | 最多展示 4000 行逐行结果，另有双方全文 |

差异使用有界 Myers，公共前后缀减少小改动成本；超过任何上限改为全文，不阻塞主编辑器。自动候选为超过 30 天或最近 100 个以外的自动快照，手动、固定、恢复前及其他重要版本默认保护。保留规则生成候选，不静默删除。

清理 token 绑定审查时的清单、名称/固定、配额和目录大小，变化后要求重新预览。先提交索引墓碑再移除清单、回收对象；所有保留文档共享引用都参与标记，中断可重试且已删除清单不会重新出现。只回收本历史目录无保留引用的对象，从不清理正文、`assets/`、其他目录历史或 IndexedDB 草稿。
