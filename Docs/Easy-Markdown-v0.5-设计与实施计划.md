# EasyM v0.5 设计与实施计划

冻结日期：2026-10-14。开发分支：`feature/v0.5`。基线：`main` 的 `4951088`（已合并 v0.4）。本阶段聚焦桌面持续使用与文件安全；本文把原完整方案中的最近打开、会话恢复和外部冲突要求细化为实施范围。版本号在最终交付步骤统一升级，开发期间保持 `0.4.0`。

## 1. 目标和边界

让用户再次打开 EasyM 时能找到未完成工作、快捷打开最近文档，并在文件被其他程序修改后理解差异、保留双方内容。Markdown 原文、现有撤销栈、编码/BOM/换行保留、图片事务和历史契约继续沿用。

本轮四步依次完成，每一步作为完整开发单元验证和记录，不拆成 A/B/C。设计参考只涉及交互设计，独立编写代码，不复制 MarkText 代码、资源或文案，也不因为设计借鉴引入其 MIT 声明。新增第三方依赖仍需独立处理许可和 SBOM。

不加入账号、云同步、多人协作、插件运行时、AI、新 Markdown 方言、DOCX 导入、直接 PDF 引擎或任意自定义 CSS。本阶段不把本机草稿/版本历史宣传为跨设备备份，也不承诺尚未经实机验证的三平台 GUI 行为。

## 2. 第一步：草稿会话索引与安全启动

### 用户行为

- 保存标签顺序和当前标签，重启后优先恢复仍有独立草稿的标签，并定位到上次活动草稿；当前标签没有草稿时选第一个可恢复标签。
- 每个草稿仍显示“恢复草稿 / 放弃草稿”，用户确认恢复后变成需另存的独立应用副本，不自动覆盖原文件、不沿用失效原生文件 ID。
- 空白且没有修改的标签、已保存且无草稿的文件，本步不伪装成能够恢复；已保存文件的会话重开在第二步实现。
- 无索引的旧版本用户沿用欢迎文档加独立草稿恢复；有效索引存在时不额外插入欢迎标签。
- 保留草稿并关闭的标签可能不再位于会话索引中，下一次仍作为独立草稿追加显示，不能因为从标签列表移除而丢弃正文。

### 数据契约

本步索引为 WebView 同源本机 `localStorage` 的 `easym-session`，版本 1。仅记录 `{ version, tabs: [{ draftKey, name }], activeDraftKey }`。正文、图片、图片操作和编码快照继续存入既有 IndexedDB，不重复存正文。索引不存原生句柄、绝对路径、正文或图片；它仅为界面布局元数据，不是文件访问授权。

读写严格校验：最多 100 条、每个名称最多 512 UTF-16 单位、读取最多 100,000 UTF-16 单位；键只接受现有 `current` 或有长度限制的 `document:*` 草稿键，键不重复，活动键必须属于索引。写入只输出白名单字段。超过 100 个实际标签时不截断草稿、不关闭标签，保留旧索引并提示索引暂停更新。

启动先读取索引、枚举 IndexedDB 键，再挂载编辑器；检查期间禁止编辑和关闭，避免迟到恢复结果覆盖用户刚刚创建的标签。按索引顺序保留存在的草稿，追加遗漏草稿。缺失草稿只从派生布局移除，不删除数据库数据。正常运行中同步记录布局，保存失败仅提示，不阻止独立草稿和正文保存。

未来版本/损坏索引及索引读取拒绝：保留原值，本次禁止重写，仍检查独立草稿。草稿枚举失败：保留原索引，允许显示默认编辑器及已有草稿错误提示，不写入不完整恢复布局。单个不兼容草稿继续走既有保护流程，不迁移或抹去未知正文格式。

此索引属于设备应用状态，与完整方案中的应用数据目录原则一致，当前采用既有 WebView 本机存储实现最小切片；第二步新增持久路径登记必须由原生端保存在系统应用数据目录，不能把前端存储变成任意磁盘打开接口。浏览器清理站点数据也会清理索引与草稿，界面不作永久保留承诺。

### 验收

重启恢复活动草稿与顺序、同名多标签、失效索引项、孤立草稿、未来格式、存储读取/写入失败、保留/放弃/保存关闭、正文和资源原有恢复流程。浏览器自动化验证真实页面刷新和 CodeMirror 输入，原生权限与真实异常退出另行记录。

## 3. 第二步：最近文件、工作区及已保存标签重开

EM 菜单新增最近打开入口，按时间展示文件和工作区，同名项显示位置，支持移除单条和清空记录；清理记录不删除原文件、草稿或版本历史。浏览器只提供明确可用的能力，不模拟原生磁盘权限。

原生端仅登记用户通过文件/工作区选择器授权或在授权工作区内成功打开、保存的目标，存入系统应用数据目录的版本化有界记录；前端以不透明记录 ID 请求重开，不允许传任意绝对路径。持久记录是用户选择的延续，绝不重用旧进程 session ID。重开时重新检查存在、类型、大小、符号链接/目录边界和读取权限，失败可移除记录或重新选择。

先文件登记和最近打开，再接入上次已保存标签顺序与活动标签重开，作为同一步完成交付。最多记忆 30 个文件和 10 个工作区；启动最多恢复 20 个已保存文件，超出部分通过最近打开访问，界面说明限制。已经打开的目标复用标签，保留内存编辑。失败只影响目标项，不阻止其他文档恢复。

有未完成草稿的目标不将草稿自动写回磁盘；先展示恢复副本并保留磁盘重新打开入口。恢复动作与新打开动作必须有代次/目标校验，避免异步完成后切走用户正在编辑的标签。新增原生记录 Schema、失败回退与同名/中文/权限/失效/越界测试在此步具体冻结并记录。

## 4. 第三步：外部变更感知与冲突对照

切回应用或标签时按受限检查策略检测已授权文件的原始字节 revision，后台检查不写正文。未修改文档提示重新加载；存在本机修改或未提交图片/表格输入时保留当前编辑，暂停可能反复冲突的自动保存并提供比较、另存副本、重新加载的明确入口。

对照显示当前内存版本和磁盘版本及文本差异，支持复制、定位和另存当前版本；重新加载前沿用未保存内容保护，不静默丢弃编辑。v0.5 不实现自动三方合并；恢复历史也要服从磁盘 revision 冲突检查。图片不通过文本对照猜测合并，资源事务仍使用原有逻辑。

检测在后台有界执行，同一文件去重、可取消并丢弃旧结果，不在每个输入事件读取磁盘。保存成功后更新基准 revision，应用自身保存不产生重复冲突。重命名、删除、权限撤销、超限文件均保留可另存的内存正文，并给出对应提示。

## 5. 第四步：回归、使用说明与开发包

补齐使用导引、样例、恢复和错误处理说明；统一版本至 `0.5.0`，更新依赖清单和许可差异，构建 Windows 安装包及开发便携包。完成前端测试/生产构建、所有生产回归和性能基线；涉及原生层时运行 Rust 测试及三平台 CI。

自动化与原生实机证据分别记录。真实中文 IME、系统文件/打印对话框、macOS/Linux GUI、屏幕阅读器、发行签名与更新能力等未解决项仍明确列出，不以浏览器 fixture 或合成事件代替。既有历史证据保持不变，新证据放入 `Docs/verification/v0.5/`。
