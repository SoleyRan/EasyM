# EasyM 2.0.0-beta.4

2.0 的主线是单用户多设备同步：在自己的几台电脑上离线写 Markdown 和图片，联网后通过自备的 WebDAV 服务器同步，冲突时保留双方。普通本地文档仍然无需账号、无需联网。这是 Beta 候选，用来收集反馈；实际发布状态以 GitHub Releases 为准。

## 新增：多设备同步

- 自备 WebDAV 服务器。已验证 Apache 2.4.69 mod_dav_fs 与 Nextcloud 31.0.14；其他服务未验证，不在支持清单内。没有 EasyM 账号，也不经过第三方服务器。
- 先在 EM →“同步身份”为工作区启用持久身份，再从 EM →“同步…”连接。连接前会预览要上传/下载的文档数，确认前不改动任何文件；两边同名的文档可选“保留两份”或“视为同一文档”。
- 修改不同段落时自动按行合并，事后在同步报告里说明。改到同一处时一份留在原位，另一份另存为“(冲突 xxxxxxxx)”副本，可在“待解决的冲突”里逐处选择；解决前的版本移到工作区回收站。
- 远端删除碰上本机修改时保留修改；打开中的文档要等标签页关闭后才会移到回收站。删除都进应用内回收站，不直接删除文件。
- 服务器从备份回滚、配置被复制到另一台机器、设备被停用时，同步停止且不改动本机文件，可以“以新设备身份重新加入”，不一致的文档另存为副本。
- 设备列表（名称、平台、上次同步时间）、停用其他设备、同步频率（1/5/15 分钟或仅手动）、同步进度、服务器空间、脱敏诊断信息。
- 工作区内的受控重命名、跨目录移动和回收站，会同步更新相对图片/文档链接、版本历史和同步身份。

密码只保存在系统凭据存储（Windows 凭据管理器、macOS 钥匙串、Linux Secret Service），不写入工作区、日志、同步对象或诊断信息。不会关闭 TLS 证书校验。同步不提供端到端加密：服务器管理员能读到正文和图片。同步不是备份，重要文档仍需异盘备份。

服务器上的数据放在 WebDAV 地址下固定的 `easym-sync/` 目录里，按同步格式保存：正文和图片以内容哈希命名，文件名和目录结构记在版本清单里，本机工作区的文件夹名不上传。所以在网页里看不到原来的文件名，这是设计如此。不要在网页里修改或删除这个目录；确认同步结果请看另一台设备。

## 编辑与界面改进

- 列表项按 Tab / Shift+Tab 缩进和取消缩进。
- 即时渲染：在代码块、表格、分隔线、图片下方用鼠标选取文字时，选中位置会比鼠标所指的低，越往下偏得越多。现在选中的就是鼠标所在的位置。
- `**注意:**后文` 这类写法无法加粗：结束符前面是标点（冒号、括号等），后面紧接中文，CommonMark 规范在这种情况下不认为它是结束符。现在在紧邻中文字符时放宽这条规则；没有中文字符的情况（如 `a**xxx:**b`）不受影响，仍然遵循标准规范。
- 嵌入的 HTML 按安全子集显示，例如 `<p align="center"><img src="images/a.png" width="600"></p>`：保留对齐、宽高等排版属性，脚本、事件处理、iframe 和不安全的链接会被移除。HTML 里的图片和 Markdown 图片一样只读取本地文件，远程图片不下载。以 `./` 开头的图片路径（如 `./images/a.png`）之前会被当成未授权而不显示，现在能正常读取。
- Mermaid：节点文字支持 `\n` 和 `<br>` 换行；支持 `style` / `classDef` 设置颜色和线宽。
- macOS：删除非空表格行/列、移到回收站等需要确认的操作，改用系统对话框确认。之前确认框不出现，操作会被直接取消。
- 中文斜体会倾斜显示。之前中文字体没有斜体字形，显示成正体。
- 阅读模式只在当前窗口内切换，不再进入全屏；同时打开文件栏和大纲时，侧栏与阅读区连成一页。退出阅读模式后，源码保持原来的滚动位置。
- 没打开工作区时，点“同步身份”“同步…”会提示先打开要同步的文件夹，不再是灰色不可点。

## 平台与安装

| 平台 | 文件 | 说明 |
| --- | --- | --- |
| Windows x64 | `EasyM_2.0.0-beta.4_x64-setup.exe`、`EasyM-2.0.0-beta.4-windows-x64.zip` | 需要 WebView2 Runtime；便携包附许可和样例 |
| macOS Apple Silicon | `EasyM-2.0.0-beta.4-macos-arm64.dmg` | 附许可；样例在仓库 `Docs/samples/v2.0` |
| Ubuntu 24.04 x86_64 | `EasyM-2.0.0-beta.4-linux-amd64.deb` | 附许可；同步密码需要 Secret Service（桌面版默认的 GNOME 钥匙环，或 KWallet）。没有时同步会提示凭据存储不可用，不会把密码写入文件 |

其他 CPU、发行版未验收。Web/PWA 与移动端延期到 2.x，2.0 只含上述三个桌面平台。

下载后与同次发行的 `SHA256SUMS.txt` 核对。当前没有代码签名、公证、自动更新或更新签名；Windows 可能出现 SmartScreen 提示，macOS 可能被 Gatekeeper 拦截（需在“系统设置 → 隐私与安全性”中选择仍要打开）。未签名的 macOS 包每次升级后，第一次同步时钥匙串可能再次询问是否允许 EasyM 使用“EasyM Sync”，选“始终允许”即可；选拒绝时同步会提示凭据不可用，连接设置不会丢失。

Linux 注意：Debian 的版本排序会把 `2.0.0-beta.4` 排在 `2.0.0` 之后（实测 dpkg）。以后从 Beta 升到正式版时，先 `sudo apt remove easym` 再安装正式版，或用 `sudo dpkg -i` 直接安装；卸载不会删除文档。Windows 安装器按 semver 比较，Beta 升正式版正常。

## 从 1.0 升级

1. 保存文档，退出 1.0。复制重要文档及旁边的 `.easym` 目录；自定义历史目录也要单独备份。
2. 安装 2.0（Windows 安装包会就地升级；便携版解压到新目录，不要混放不同版本）。不要为了升级清理 WebView 应用数据，否则本机未落盘的草稿会丢失。
3. 首次启动会显示“已更新到 EasyM 2.0.0-beta.4”导引。

应用标识（`com.easym.markdown`）、草稿、最近文件、版本历史、合并恢复记录、图片元数据（`.easym/images.json`）和单文档备份格式都与 1.0 相同，升级不迁移、不改写任何已有文件。不启用同步时，2.0 对工作区的写入与 1.0 一致。

启用同步后新增的数据：

| 位置 | 内容 | 说明 |
| --- | --- | --- |
| 工作区 `.easym/sync/workspace.json` | 工作区 ID、文档相对路径与文档 ID | 不含地址、账号或设备路径 |
| 工作区 `.easym/sync/operations/` | 重命名/移动的崩溃恢复日志 | 完成后清理 |
| 工作区 `.easym/trash/` | 应用内回收站 | 用户删除、远端删除、冲突解决前版本 |
| 应用数据目录 `sync/` | 连接（地址、用户名）、设备身份、同步状态、对象缓存 | 不随工作区复制 |
| 系统凭据存储，服务名 `EasyM Sync` | WebDAV 密码 | 每个连接一条 |
| 服务器 `easym-sync/` 目录 | 不可变对象、每设备记录、设备信息、停用记录 | 不是普通 Markdown 目录，不要用其他工具直接编辑 |

## 关闭同步、卸载与回退到 1.0

- 退出同步（“同步…”→“退出同步”）：删除本机的连接、密码、同步状态和缓存，工作区文件与服务器数据不动。之后可重新连接；重连时选择加入原工作区即可，不会重复下载内容相同的文档。
- 停用同步身份（“同步身份”→“停用”）：只删除 `.easym/sync/workspace.json`，正文、图片和历史不受影响。要彻底恢复成普通 Markdown 目录，先退出同步，再停用身份，最后可手动删除 `.easym/sync/` 和不再需要的 `.easym/trash/`。
- 卸载：不会删除文档、`.easym` 目录或系统凭据。Windows 卸载程序里的“删除应用程序数据”复选框会同时删除本机草稿、最近文件和同步状态，保留它们就不要勾选。卸载前先在 EasyM 里退出同步，凭据会一起删除；已卸载的话，可在 Windows 凭据管理器、macOS“钥匙串访问”或 Linux 的“密码和密钥”中删除 `EasyM Sync` 条目。
- 回退到 1.0：先在 2.0 中退出同步，再安装 1.0。1.0 不认识同步数据，会忽略 `.easym/sync/`、`.easym/trash/`（以点开头的目录不在文件树中显示），正文、图片、历史和备份都可以照常打开。不要让 1.0 和 2.0 同时编辑一个仍在同步的工作区：1.0 的改名、复制和删除不会记录身份。回到 2.0 后，2.0 每次同步都会按原始字节重新扫描，1.0 期间的修改会作为本机修改上传。在 1.0 里删掉的文件不会被当成删除发布，其他设备上仍保留；要删除请回到 2.0 用工作区回收站。在 1.0 里复制或改名产生的文件会按新文档加入，改名的话其他设备上会同时留有旧名和新名两份，需手动删掉旧的一份。

## 不同版本的设备混用

同一个同步工作区里的所有设备都应升级到同一个 2.0 候选。开发阶段第 4 步及更早的构建不认识设备停用记录（`retired/`）：被停用设备的记录从服务器消失时，这些旧构建会把它当成服务器回滚，停止同步并要求重新加入。升级到本候选后按提示“以新设备身份重新加入”即可，本机文件不会被改动。1.0 不含同步功能，不受影响。

## 出问题时如何恢复

- 先停下来：在“同步…”里点“暂停”。暂停、断网、凭据失效都不影响本机编辑和保存。
- 被同步覆盖或合并后想要原来的版本：冲突解决前的版本在工作区回收站（侧栏“工作区回收站”）。同步写入不会生成版本历史快照，不要依赖“版本历史”找回同步前的内容；需要的话，在大规模同步前手动记录快照或做单文档备份。
- 文档不见了：先查工作区回收站；远端删除和本机删除都先进回收站，恢复时不覆盖已有文件。
- 同步停止并提示服务器回滚、设备身份被占用、本机已被停用：本机文件没有改动。确认服务器状态后，用“以新设备身份重新加入”，与服务器不一致的文档会另存为冲突副本；在“设备”里停用不再使用的旧身份。
- 服务器数据丢失或损坏（提示缺少同步数据）：本机文件保留。可以退出同步，在服务器上换一个空目录或删掉 `easym-sync/`，再从数据最完整的那台设备“作为新的同步工作区上传”，其他设备随后加入并在同名冲突时选择“保留两份”。
- 反馈问题时附上“空间与诊断”→“复制诊断信息”的内容：只含错误码、数量和 8 位短 ID，不含文档内容、文件名、服务器地址或密码。

## 发行边界

- 同步：只支持一个用户的多台设备，不做多人协作；单个正文 10 MiB、单张图片 20 MiB；行级自动合并限 2 MiB 且不处理 BOM、NUL 和混合换行的正文（这些情况保留双方）。首发不自动清理服务器上的旧对象和删除记录，空间只增不减；Apache 不报告空间，Nextcloud 只报告已用空间。
- 实测规模：2,000 个文档的本地扫描约 0.44 秒；Nextcloud 上 300 个文档的首次恢复约 29 秒，更大规模和公网延迟下未实测。
- 1.0 的边界仍然适用：PDF 使用系统打印；DOCX 中公式和 Mermaid 保留可编辑源码；即时渲染在超过 1 Mi 字符或 20,000 字符单行时降级为源码；远程图片保留链接，备份不下载。
- 自动化覆盖：同步核心与界面的确定性测试、Apache/Nextcloud 实际服务的端到端故障矩阵、Windows 原生启动与 CI 隔离安装/卸载。真实输入法、原生对话框、系统凭据存储、打印和读屏需要实机确认，见[实机验收表](Easy-Markdown-v2.0-实机验收.md)；未勾选不代表通过。
