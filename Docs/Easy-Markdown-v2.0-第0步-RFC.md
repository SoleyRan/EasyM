## 2. 当前实施决策

首发目标为 Windows x64/WebView2、macOS Apple Silicon/WKWebView、Ubuntu 24.04 x86_64/WebKitGTK，先实现同一用户两台桌面的文件同步。三平台均需真实 GUI 和凭据存储验收；Web/PWA、Android/iOS 切片可另立后续分支，不列为本轮首发阻断项。

首个 Provider 选择 WebDAV 做验证，不新增 EasyM 账号或服务器。第 1 步比较两个固定版本目标：Nextcloud WebDAV、Apache httpd mod_dav；实际版本和支持结论由该阶段报告确定。若无法满足条件更新契约，暂停可写接入并在独立变更中评估 Git，不同时开发两个 Provider。

同步数据使用 EasyM 专用远端命名空间；用户本地仍是 Markdown 和图片目录。同步包含已保存正文、可移植路径和当前文档所需图片/实例元数据（包括保留编辑能力所需源副本）；未保存草稿、旧历史、凭据、最近文件、窗口设置和设备日志留在本机。TLS 与原生凭据存储为前置条件；首发不提供 E2EE，也不自动清理远端旧对象。

## 3. 稳定身份与 1.0 兼容

| 已有数据 | 现有行为 | 2.0 规则 |
| --- | --- | --- |
| Storage 打开 ID | 进程内 UUID，重启可变 | 仅作授权句柄，绝不能作为同步 documentId |
| history index 的 documentId | 文档所在目录的历史索引，可能重定位到用户目录 | 通过原生 history 服务读取；唯一且可验证的 ID 优先沿用，不由前端猜测历史路径 |
| Draft.documentId | 可选字段；当前草稿写入流程未保证填写 | 不作为现有持久身份的可靠来源；旧草稿结构不迁移 |
| ImageInstance.documentId | 可为 null；目录级 images.json 含多文档实例 | 实例按正文引用筛选，单文档同步快照不能直接复制整个目录元数据 |
| 备份恢复 | 恢复到新目录，可能携带原身份 | 按“新文档副本”默认分叉；显式灾难恢复后才重新绑定旧同步身份 |

第 2 步新增 `.easym/sync/workspace.json`（schemaVersion=1），记录 workspaceId 和相对文档路径到 documentId 的映射；该文件只保存可移植身份，不保存设备绝对路径、端点或凭据。不向现有 images.json/history schema 塞入同步队列。设备游标、队列、基线对象及绑定配置放平台应用数据目录，以本机绑定 ID 分区。

首次启用显式预览和归档；已有有效历史 ID 唯一时沿用，没有则生成 UUID；同一工作区出现重复 ID/大小写冲突/不可读元数据即暂停相关文档接入，不凭内容哈希认亲。不同本地历史 ID 与远端同名文件首次接入时要求选择保留双方或绑定，必要时保留 `sync documentId ↔ local history documentId` 映射，禁止改写旧快照的身份。

重命名/移动保留身份，另存/复制默认新身份；外部工具移动缺乏证据时进入协调，不能仅凭内容相同自动推断。跨目录移动还需原生历史迁移、目录级图片引用和文档链接事务；本阶段不实施迁移。

旧版 EasyM 不认识同步元数据，也无法阻止旧应用写入。新版每次扫描必须以原始字节和资源元数据检查外部变化，不相信身份文件就代表文件未变。旧版新增/复制/重命名后身份不确定的文档暂停同步并提示协调。回退先停止绑定、保留普通 Markdown+图片副本；不能承诺旧版可安全参与同步。

## 4. 最小远端协议

> 2026-10-21 第 1 步修订：实测 Apache 2.4.69 会同时确认多个条件写入，Nextcloud 31.0.14 会同时确认多个首次创建（见[能力报告](Easy-Markdown-v2.0-第1步-WebDAV能力报告.md)），原“全局头指针 + 条件更新”不可靠。改为每设备单写者日志，正确性不依赖服务端 CAS。

相对授权端点建立 `easym-sync/v1/<workspaceId>/`：

| 位置 | 内容和写入方式 |
| --- | --- |
| `objects/sha256/<hex>` | 原始正文、图片、实例元数据及提交清单的不可变字节，创建后不得覆盖；摘要按实际字节计算，同摘要并发创建内容相同，竞争无害 |
| `devices/<deviceId>.json` | `{schemaVersion:1, workspaceId, deviceId, sequence, commitHash}`，最大 4096 字节；只由该设备写入，每次发布 sequence 加 1 |

设备头不是文档内容，也不包含凭据、时间戳、用户路径或远端 URL。commitHash 指向工作区提交清单（schema 1，`src/core/sync-commit.ts`）：schemaVersion、workspaceId、operationId、deviceId、父提交、文档条目及 tombstone。设备提交至多一个父；合并提交以保留作者 `00000000-0000-4000-8000-000000000000` 记录，恰有两个升序父，operationId 由父提交派生。编码按固定字段顺序与路径排序，对象寻址按原始字节。

一轮同步（`src/core/sync-log.ts`）：确认上次未决的设备头写入；列出并读取全部设备头；上传本地新提交（先对象后清单）；去掉被其他提示包含的祖先后，按摘要排序依次确定性合并；最后只推进本设备头。任意设备合并同一对提示得到逐字节相同的提交，因此谁先合并都收敛到同一结果。

合并按 documentId 三方比较，基线取全部最低公共祖先且须一致，否则按无基线处理。路径与内容分别合并：一侧改名、另一侧改内容可自动合并；双方改内容时按内容摘要确定原位保留者，另一版本以派生身份保存为冲突副本（复用同一对象）；编辑优先于删除；不同文档落到同一大小写折叠路径时较大 documentId 改名。已确认的编辑不被丢弃。

原生 Provider 管理 HTTP、凭据、限额、摘要验证、超时和授权；接口见 `src/core/sync-contract.ts`。设备列表必须完整：未知条目、非 207 响应或列出后读不到的头一律报错；读头为空只代表真实 404，401/403/解析失败报错。写本设备头优先带强 ETag 的 If-Match；服务只给弱 ETag（Apache 修改后 1 秒内）时允许无条件写本设备头，因单写者且写前已回读确认。

写入前先在本机持久化 pending（sequence、commitHash）。响应丢失或取消后，下一轮回读本设备头：等于 pending 即完成，等于旧值即丢弃重算，其他值视为同一 deviceId 被另一安装使用并停止同步。其他设备头 sequence 低于本机已见值或已见设备消失，判为回滚并停止，不复活旧状态。引用的提交缺失或摘要不符时拒绝应用。设备头数量超过 64 时暂停而非截断。

拉取先验证对象和路径，落地前再次检查磁盘版本和编辑器 dirty；与原有原生写入队列串行。同步前恢复归档独立于用户可选历史，并有配额上限；空间不足时停止应用远端修改。本地日志保证失败/退出可恢复，目录级图片元数据须按文档合并而非整份覆盖。同步不绕过现有冲突、草稿和图片事务。

## 5. 错误、约束与规模预算

设备头解析器拒绝未知 schema、无效 UTF-8/JSON、跨工作区、内容与位置不符的 deviceId、保留合并作者、非正整数 sequence、非规范 ID/摘要和额外字段。清单解析器另拒绝跨平台不可移植路径、大小写折叠后重复路径、重复身份和超出 1.0 限额的资源。解析成功只证明结构有效；对象读取时按摘要校验。任何网络返回均视为不可信数据。

远端随设备数和历史增长：每轮读取全部设备头（O(设备数) 请求），合并时按需读取祖先提交，单轮历史读取上限 10000 个提交，超限暂停。第 1 步回环实测见能力报告；完整历史压缩（检查点）与远端回收不在首发范围。

首发验证预算暂定：一个绑定工作区 1000 个文档、2000 个去重图片对象、当前快照总量 512 MiB；单正文仍受 1.0 的 10 MiB、单图片 20 MiB、单文档图片 128 MiB 限制。队列批量处理、同时最多 2 个对象传输；不一次性把整个工作区读入内存。上述为实现/测量目标而非已验证支持承诺，第 1 步依据实际清单大小、服务限制和传输测量收紧，超限显式暂停而非截断同步。

首发禁止自动 GC。tombstone 不按本机时间自动过期；长期离线设备/停用设备归来先全量协调。认证失败暂停，限额/空间不足保持本地可写，重试有退避和上限。诊断仅输出错误码、操作 ID、大小和阶段，默认不含正文、端点凭据或完整用户路径。

## 6. 验证方法与样例

第 1 步使用独立测试账户和新建命名空间。双设备指两个独立本地目录、设备 ID、队列和进程；不得用同一数据库冒充两台设备。服务测试命名空间不能复用日常数据。

| 样例/故障 | 方法与通过条件 |
| --- | --- |
| 字节保真 | UTF-8/BOM、LF/CRLF/混合换行、中文/emoji、未知 Markdown；未编辑正文往返字节摘要相同 |
| 图片与元数据 | 引用同图的两文档、不同裁剪实例、嵌套相对路径；恢复后正文及源/展示图摘要相同，目录其他实例不变 |
| 并发设备 | 多个独立设备同时编辑共享与各自文档并并行同步；全部收敛到同一提交，所有未被设备有意替换的编辑原位或以冲突副本保留 |
| 同一设备 ID 双安装、回滚 | 第二个安装使用同一 deviceId 或设备头被恢复为旧版本/删除；停止同步，不覆盖、不复活 |
| 响应丢失 | 设备头写入在服务应答后或发送后断开；结果 unknown，下一轮回读本设备头确定完成或重算，无重复与丢失 |
| 对象不完整 | 截断/损坏/丢失图片或清单；拒绝推进头或拒绝落地，不显示已同步 |
| 外部修改/旧版写入 | 接收前修改本地正文/图片；保存版本复核触发冲突，保留本地修改 |
| 路径/身份 | 大小写冲突、重复 ID、Unicode 路径、越界和符号链接；拒绝危险应用，正常中文路径可往返 |

第 0 步只执行头指针信任边界单测和 TypeScript/已有单测回归。第 1 步以 `pnpm verify:webdav` 对两个服务执行并发设备、响应丢失、双安装、回滚、损坏对象、取消和未知条目检查；字节保真、图片、外部修改和本地路径落地属于第 2/3 步，这里的矩阵不冒充已执行的验证。

性能在固定 OS/CPU/内存及 WebView 上分别记录：1.0 大文档输入 p95（目标≤50ms）；100/1000 文档冷启动和索引耗时；首轮/单文档增量同步耗时、请求数、传输字节及峰值内存。网络用 50Mbps/50ms 与 1Mbps/200ms 两档记录，两个服务版本分别留存结果。第 1 步冻结可复现测量入口，第 3 步以后才作为端到端性能验收。
