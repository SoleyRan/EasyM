# EasyM v2.0 设计与实施计划

创建日期：2026-10-20。状态：已进入分阶段实施；第 0 步交付见 [RFC](Easy-Markdown-v2.0-第0步-RFC.md) 与[验收记录](Easy-Markdown-v2.0-第0步-验收与交付.md)。

## 1. 基线与目标

维护者已确认 1.0 发版完成。第 0 步核实 main、`v1.0.0` 标签与[正式 Release](https://github.com/SoleyRan/EasyM/releases/tag/v1.0.0) 目标均为 `39fc43cadc08be6f1e564499b360137e58d4a23e`，对应 [Validate EasyM 39215035819](https://github.com/SoleyRan/EasyM/actions/runs/39215035819) 成功。三平台发布资产及核实范围见 RFC；本轮未重新检验发布包或签名。历史验收文件作为当时记录保留，不补填未经实际操作的结果。

沿用[完整设计方案](Easy-Markdown-完整设计方案.md)第 16、20、22 章：2.0 主线为单用户多端同步。用户可以在自己的两台设备离线编辑 Markdown 和图片，联网后同步，冲突时保留双方并可恢复。普通本地文档继续无账号使用，联网同步由用户主动配置和启用。

当前实施基线先交付桌面双设备同步：Windows x64、macOS Apple Silicon、Ubuntu 24.04 x86_64 复用同步契约，按正式支持矩阵验收。Web/PWA、移动端单独做可行性切片，通过后决定纳入 2.0 还是后续 2.x；它们不作为首发阻断项。该范围按原路线及继续开发指令落地，如需扩展首发平台，应单独修订 RFC 与验收矩阵。

## 4. 首个 Provider：先验证再冻结

首个 Provider 选择用户自备的 WebDAV 进行验证，不新增强制 EasyM 账号。Git 为备选；2.0 首发只实现其中一个。WebDAV 不是“支持协议即可安全覆盖”：必须验证目标服务的条件创建、ETag/If-Match、并发提交、超时后结果查询和一致性。不能满足契约的端点拒绝开启可写同步，或明确降级为导入/导出；不伪装成已同步。

远端采用受 EasyM 管理的命名空间，保存不可变正文/资源对象、提交清单和条件更新的工作区头指针。桌面本地仍使用正常 Markdown 目录。该远端布局不是通用云盘文件夹镜像，不能承诺第三方编辑器直接编辑远端内部对象。若维护者要求远端直接呈现可编辑 Markdown 树，需重新评估提交一致性和第三方写入冲突后再冻结。

第 1 步至少选两类实际目标服务记录版本、能力和故障结果，随后公布明确支持清单。使用模拟 Provider 做确定性故障验证，同时用实际服务验证协议语义；两者不能互相替代。禁止关闭 TLS 校验来绕过配置错误；凭据由原生凭据存储管理，不写入工作区、日志或同步对象。跨域重定向不得自动携带凭据。

## 5. 数据与同步契约

- `documentId` 和 `workspaceId` 为持久身份，路径仅用于定位。沿用现有有效身份；同内容文件不能仅凭哈希认作同一文档。另存/复制默认产生新身份；重命名/移动保持身份。重复 ID、外部复制和未知重命名进入可审查的协调流程，不能猜测后删除另一份文件。
- 原始字节摘要、编辑器 textRevision、本地文件 revision、远端不透明 revision 分别保存；时间仅显示，不决定覆盖顺序。保留 BOM/换行策略，不为同步重写未编辑正文。
- 明确 `.easym` 现有格式与同步新元数据的边界。新 schema 可探测、有迁移前快照、失败可恢复；旧版本读取/写入行为必须实测。不得默认旧版能安全编辑已启用同步的工作区；不兼容时提供关闭同步后的普通 Markdown 导出和说明。
- 上传先写不可变资源和正文，校验后生成清单，最后条件更新远端头指针。条件失败重新取远端并比较共同祖先，不能盲重试覆盖。超时后通过 operationId/提交状态查询判定结果，避免重复提交。
- 下载先完整校验字节与依赖，再在本地带日志提交。提交前复核磁盘 revision 和编辑器未保存状态，复用既有外部冲突保护；不能因本地“无任务”就假定文件没变。启动时先恢复未完成事务，再继续同步。
- 未保存草稿保持本地；已命名文档以成功落盘的版本入队，编辑期间新的修改继续保存并生成后续任务。同步失败、暂停和凭据过期不阻断离线写作。
- 删除使用 tombstone；删除与编辑冲突保留编辑副本。设备有显式注册、停用和恢复规则；长期离线/已停用设备回归须全量协调，不能自动复活删除。首发不自动清理远端不可变资源和 tombstone，设置配额/空间提示；回收策略单独验证后开放。
- 队列持久记录 operationId、依赖、基线、重试和已提交状态，重启可幂等恢复；重试有退避和上限，鉴权错误暂停。取消的结果需核对远端是否已提交。
- “本地已保存”“待同步”“同步中”“已同步”“冲突”“暂停/失败”显示真实状态。只有目标提交和资源均验证成功才显示已同步；用户修改、外部变更、远端新版本均可能使状态失效。同步不是独立备份。

## 6. 分阶段实施

各阶段完成后再进入下一阶段。工期在第 0、1 步验证后估算，不预设发布日期。

| 阶段 | 工作 | 交付与退出条件 |
| --- | --- | --- |
| 第 0 步：范围与 RFC | 核对 1.0 发布基线、最新 CI；确定首发设备、Provider 验证方向、远端布局、隐私/加密边界和规模预算；列出兼容矩阵 | RFC、最小 Provider 契约、头指针解析测试、代表性场景与性能测量方法；关键实施决策明确，真实服务支持结论留到第 1 步 |
| 第 1 步：Provider 验证 | 两类实际 WebDAV 服务的条件提交/超时/并发切片；失败时再评估 Git | 能力报告、最小双客户端竞争演示；支持清单与 Provider 选择冻结 |
| 第 2 步：身份与本地协调 | 持久身份、迁移、快照、受控重命名/移动/删除及相对图片/文档链接处理；同步所需接口抽取 | 旧版样例、复制/另存/外部改动、失败回滚通过；离线功能回归通过 |
| 第 3 步：单设备往返 | 凭据管理、首次配对/预览、资源/清单、拉取推送、持久队列、暂停和退出同步 | 设备 A 上传后清空隔离配置，设备 B 可完整恢复正文与图片；重复/崩溃重试无损 |
| 第 4 步：双设备冲突 | 共同祖先、三方合并、冲突 UI、删除/移动、离线回归、远端回滚识别 | 双设备故障矩阵全部通过；无祖先或回滚时保守保留副本，不静默覆盖 |
| 第 5 步：产品与跨端切片 | 同步设置、状态/错误、任务列表、空间提示、诊断脱敏；Web/PWA 与移动做独立切片 | 桌面同步可日常使用；Web/移动各有继续/延期结论和实际平台证据 |
| 第 6 步：Beta 与发布 | 升级/回退、三平台 GUI/输入法/凭据验收、长时间离线试用、依赖许可和包验证 | 无数据损坏阻断项；Beta 反馈闭环；同提交候选、签名/更新说明和恢复文档齐全 |

每阶段交付可追溯验收记录，记录基线、环境、结果和适用范围；有实际服务或平台验证时，在 `Docs/verification/v2.0/step-N/` 留存脱敏证据和版本。原始本地日志存放于被忽略的 `test-results/v2.0/step-N/`。不复用 1.0 通过状态，不提前改 package/Cargo 为 2.0.0。

## 7. 验收矩阵

| 场景 | 必须满足 |
| --- | --- |
| 首次接入：本地空/远端空/两侧都有文件 | 操作前预览范围；同名异内容不静默覆盖，取消不破坏原数据 |
| A 编辑后 B 拉取；B 再编辑后 A 拉取 | 正文、图片副本、实例元数据和路径一致；双方均可独立导出普通文档 |
| A/B 离线同改、同图不同裁剪 | 无冲突可合并；冲突时保留共同祖先和双方可恢复副本，不破坏其他实例 |
| 重命名/移动与编辑；删除与编辑 | 身份连续、相对链接可核对；编辑副本不会被另一端删除吞掉 |
| 上传中断、提交成功但响应丢失、重复任务 | 不引用缺失资源；重试幂等；状态不虚报完成 |
| 下载/本地提交时应用退出或磁盘满 | 重启恢复一致版本或保留旧版本，无可见半成品覆盖 |
| 本地磁盘被其他工具修改、编辑器有新修改 | 提交前版本检查；走冲突保护，保留未保存编辑 |
| 401/403、证书错误、权限撤销、配额不足 | 停止危险重试并说明修复动作，继续离线保存，不泄露凭据 |
| 远端回滚、丢失对象、长期离线设备回归 | 校验失败阻止应用；保留本地副本并进入重新协调 |
| 恶意清单/路径/资源、重复身份、不同大小写路径 | 拒绝越界、哈希不符和身份歧义；按三平台路径语义预检 |
| 升级/关闭同步/重新安装/旧版回退 | 本地正文和图片可读；凭据与设备状态不随普通导出泄露；恢复步骤可执行 |

性能先使用现有大文档/图片样例作为回归基线，保留常规输入 p95 不超过 50 ms 的目标并在固定机器实测。同步测量另记录文档数、总字节、网络、往返次数、首轮/增量时延、队列内存及 UI 卡顿。工作区规模、单对象上限、空间预算和完成时延在第 0、1 步用实测冻结，不沿用当前搜索扫描上限作为同步容量承诺。
