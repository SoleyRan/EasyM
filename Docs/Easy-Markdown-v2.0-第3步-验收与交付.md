# EasyM v2.0 第 3 步：验收与交付

分支：`feature/v2.0-step-3-sync`，从 main `0cfb2b5`（第 2 步合并）创建。分三次提交：3A 原生 Provider 与凭据、3B 快照与远端应用、3C 同步界面与端到端往返。本记录随各子阶段更新。

## 3A：原生 WebDAV Provider、凭据与本地缓存（2026-10-23）

### 依赖决定

维护者选定：

- HTTP：`reqwest =0.13.5`，只开 `rustls` 与 `http2`。证书用平台校验器验证，不使用 native-tls，也不启用 cookies 和压缩。
- 凭据：`keyring =3.6.3`，各平台使用原生后端：Windows 凭据管理器、macOS 钥匙串、Linux Secret Service（纯 Rust 加密）。

本机目标 `x86_64-pc-windows-msvc` 的依赖从 563 个增至 619 个。新增 56 个包，均为 MIT、Apache-2.0、ISC、BSD-3-Clause 或其组合许可，无移除。`generate-notices` 在严格模式下许可文本齐全，`verify-notices` 通过。macOS 和 Linux 的许可清单由 CI 在各自平台生成。

### 交付内容

- [原生模块](../src-tauri/src/sync_native.rs)：
  - 绑定：保存在应用数据目录 `sync/bindings-v1.json`，记录 bindingId、本地工作区路径、workspaceId（取自第 2 步的同步身份）、deviceId、服务器地址和用户名。每个工作区目录只能绑定一次。WebView2 测试配置下与最近记录一样隔离。
  - 密码：每个绑定在系统凭据存储中存一项，不写入任何文件。凭据存储不可用时直接报错，不退回到文件存储。返回给界面的绑定信息里没有密码，也没有本地路径。
  - 地址：只接受 HTTPS；只有 `localhost`、`127.0.0.1`、`::1` 允许明文 HTTP，用于本机测试。地址里不能带用户名、密码、查询参数或片段。
  - 请求：
    - 禁用自动重定向，遇到重定向报 `endpoint_redirected`，避免凭据被带到其他站点。
    - 每个请求的地址都必须落在 `easym-sync/v1/<workspaceId>/` 之下。
    - 响应大小有上限：设备头 4 KiB，对象 32 MiB，目录列表 1 MiB。
  - 协议：
    - 设备列表：PROPFIND Depth 1，按本地名解析 `href`（兼容 `d:`、`D:` 和无前缀写法）并做百分号解码。如果出现未知条目、href 不在本目录下，或设备超过 64 台，就报错，不会悄悄返回更短的列表。
    - 写设备头：本机只能写自己 deviceId 的头。三种写法：首次创建（If-None-Match）、按已知版本写（If-Match）、单写者直接写（第 1 步规则）。超时或连接中断时结果记为 unknown，由核心回读本设备头来判定。
    - 对象：上传只新建、不覆盖，同摘要重复上传时校验远端已有内容。Nextcloud 返回 423 时退避重试。
  - 本地对象缓存：放在 `sync/<bindingId>/objects/`，只存经过摘要校验的不可变对象。读缓存时会再校验一次，损坏的条目直接丢弃并重新下载。
  - 同步状态：`sync/<bindingId>/state.json` 由核心写入，写入时校验其中的 workspaceId 和 deviceId 与绑定一致。
  - 退出同步：删除绑定、凭据、同步状态和缓存，不碰工作区和远端数据。
- [前端适配](../src/platform/sync-native.ts)：`NativeSyncProvider` 实现核心的 `SyncProvider`。设备头字节仍由 `src/core` 解析；对象读取后再按摘要校验一次。拒绝访问其他工作区命名空间、写其他设备的头、已取消的调用，这三种情况在发起 IPC 之前就拒绝。错误码配有中文说明。

## 3B：本地快照、远端落地与同步引擎（2026-10-24）

### 交付内容

- [快照规则](../src/core/sync-snapshot.ts)：
  - 提交条目：从本地正文生成。只收录正文引用的 EasyM 管理图片（显示图和源图），每个文档单独生成一份图片元数据，去掉进程内的 documentId，键排序固定，相同内容得到相同摘要。引用的图片缺失时，这个文档本轮不发布。
  - 本地变更 `localChange`：
    - 找不到的已登记文档沿用上一版，不算删除。
    - 只有在应用内移到回收站的文档才生成 tombstone，并且要求远端版本仍是同步时的版本；远端之后又改过的，按“编辑优先于删除”保留。
    - 未变化的文档不重新读取；只上传远端还没有的对象。
  - 落地计划 `planApply`：
    - 只覆盖、移动或删除仍处于基线版本的文件。
    - 本地也改过、或者有未保存编辑的文档，原文件保持不动，远端版本另存为“（同步副本）”。副本 ID 由原文档和远端正文摘要决定，所以中断后重试只会补写，不会重复生成。
    - 远端删除如果碰上文档正在标签页中打开，先延后执行。
    - 新文件的路径会避开磁盘上已有的路径和身份文件中登记的路径。
    - 已登记但本地缺失的文档写回原路径。
  - 配对预览 `previewJoin`：列出要下载的数量、要上传的数量，以及同名冲突。
- [同步引擎](../src/core/sync-engine.ts)，一轮的顺序如下：
  1. 先确认上次未决的设备头写入。
  2. 把磁盘补齐到本设备已发布的头。补齐失败就结束本轮，不发布本地修改，避免把还没落地的远端变更回滚。
  3. 处理延后的远端删除：标签页已关且文件未改的才移到回收站。
  4. 为新文档自动登记身份，只处理没有歧义的；共用或无法校验的历史 ID 留给“同步身份”对话框处理。
  5. 构建本地变更，交给 `runSyncPass` 推送并合并。
  6. 把合并结果落到本地。由远端新建的文档，先写身份、再写文件。单个文件失败会记入报告，下一轮用新的版本重试。
- [原生本地层](../src-tauri/src/sync_local.rs)：
  - 完整扫描，一次返回身份文件字节、每个文档的版本和历史 ID；目录不可读就报错。
  - 读取正文和所在目录的图片元数据；读取管理图片，限 20 MiB，路径必须是受管理的格式。
  - 写入走既有的日志式保存：图片不覆盖，`images.json` 合并，按版本检查。按需创建目录，拒绝隐藏目录和无法跨平台保存的文件名。
  - 远端移动复用第 2 步的日志式移动，并按需创建目标目录；远端删除走应用内回收站。
  - 正在标签页中打开的文档拒绝覆盖、移动和删除。
  - 回收站列表增加了删除时的版本字段。
- [桌面宿主](../src/platform/sync-host.ts)：把引擎接到上面的原生命令。身份文件的写前条件取原始字节的摘要（原生端写出的键顺序可能不同）。引擎状态在顶层带上 workspaceId 和 deviceId，原生端写入前会核对这两个值。

## 3C：同步界面、自动同步与端到端往返（2026-10-24）

### 交付内容

- [同步对话框](../src/editor/SyncDialog.tsx)，入口在 EM 菜单的“同步…”，需要桌面版并已打开工作区：
  - 未连接时：
    - 填写地址和账号后“检查连接”，此时什么都不写。
    - 选择“作为新的同步工作区上传”或“加入服务器上已有的工作区”。工作区自己的 ID 已在服务器上时，自动选中加入并预览。
    - 预览列出下载数、上传数、设备数和同名文档。同名文档有两个选项：
      - 保留两份：远端版本另存为“同步副本”。
      - 视为同一文档：内容相同不重复下载；内容不同时，远端版本另存为副本。
    - 确认之前不改动任何文件。
  - 已连接时：显示状态和上一轮结果（上传、下载、冲突副本、编辑优先于删除、恢复、延后删除、未上传、写入失败），提供“立即同步”“暂停/继续”“退出同步”。退出同步要先确认，只删除本机的连接、密码和同步状态。
- 标签栏状态标签：已同步、同步中、同步重试、同步暂停。点击打开对话框。
- [同步控制器](../src/platform/sync-controller.ts)：
  - 每 60 秒一轮；文档保存后立即请求一轮；同一时间只跑一轮，期间的请求合并为一次补跑。
  - 失败处理规则见 [`sync-schedule.ts`](../src/core/sync-schedule.ts)：
    - 网络、服务器繁忙、回复丢失：按 10 秒、30 秒、2 分钟、10 分钟退避重试。
    - 凭据、证书、重定向、回滚、复制设备、数据损坏、配额，以及未知错误：暂停，并显示原因。
  - 用户主动暂停按绑定记住，重启后仍是暂停。关闭工作区会中止正在进行的那一轮。
- 打开中的文档：
  - 没有未保存编辑的，同步可以覆盖或移动它，之后标签页原位重新加载。原生会话随移动指向新路径；`sync_local_open` 按会话报告当前打开的文档。
  - 有未保存编辑的，不重新加载、不覆盖；远端版本写成副本。如果用户在同步写入之后才开始编辑，保存时会走既有的外部修改检查。
  - 远端删除仍要等标签页关闭后才执行。
- 配对：
  - [`sync-pairing.ts`](../src/platform/sync-pairing.ts) 通过只读的 `sync_probe_workspace` 读取远端每个设备头和它指向的提交，校验摘要后计算预览。
  - 加入时，先把远端 workspaceId 写入身份文件；如果选择“视为同一文档”，再按路径（大小写不敏感）接管远端 documentId。旧 ID 保留为历史映射，从不按内容认亲。
  - 绑定失败时，身份文件写回原样。
- 引擎修复（真实服务器端到端测试中发现）：
  - 问题：两台设备各自新建了同名文档时，同一轮应用里会先把本地文档移走，再在原路径新建另一份文档。旧代码在移动之前登记新身份，并把之前读到的旧身份副本整份写回，结果出现重复路径，同时撤销了移动对身份的更新，表现为 `path_conflict`。
  - 修复：新身份分两段登记；会被本轮移动或删除腾出的路径，在移动或删除之后再登记，并且每次都基于最新扫描到的身份。新增了对应的双设备测试。

### 未验证与已知限制

- 没有做原生 GUI 实机操作，所以系统凭据存储的真实读写、TLS 证书错误、桌面原生命令下完整的端到端流程都还没验证。端到端检查用的是行为与原生命令一致的目录宿主。
- 每轮同步会重新扫描并哈希全部 Markdown 文件。远端对象已经有本地缓存，提交内容按需读取。大工作区的耗时和请求数留到第 5 步测量。
- 同一文档两边都改时，保存为冲突副本，不做行级合并；行级合并和冲突界面在第 4 步。
- 未保存的草稿和新建但未命名的文档不参与同步。
