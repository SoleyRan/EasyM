# v0.7 第2步：冲突选择与安全应用

完成日期：2026-10-16。分支 `feature/v0.7`，第1步已提交为 `12d8b8f`（`feat: add read-only three-way merge analysis`）；本文记录其后的第2步工作区实现与本机验收，尚未提交或推送。产品版本保持 `0.6.0`。范围见 [冻结计划](Easy-Markdown-v0.7-设计与实施计划.md)。

## 使用方式

桌面版打开已保存文件，外部程序修改后切回 EasyM，在外部变化提示中打开“比较外部版本”→“分析三方合并”。

1. 无交叠的文本修改自动组成候选；有交叠时，逐块选择“采用本地”“采用磁盘”或“手工编辑”。手工结果留空表示删除整个片段，不注入冲突标记。
2. 审查完整候选。冲突每页 20 处、候选每页最多 200,000 字符，均可翻页；三方冲突片段各展示前 20,000 字符，双方完整正文在下方可复制。候选无效或超过上限时显示原因并禁止应用。
3. 明确选择沿用本地或采用磁盘的 UTF-8/BOM 与 LF/CRLF 格式。混合换行在本次合并中统一为 LF，选项中明确提示。
4. 勾选“已审查完整候选及保存格式”，再点击“应用合并并保存”。改变冲突选择、手工输入、保存格式或分析输入会清除确认；未解决全部冲突、缺少基线或输入法正在组合时不能应用。
5. 合并成功后可以一次撤销/重做整个正文修改。撤销会恢复合并前的本地正文，但之后的自动保存仍以最新磁盘基线检查，不把磁盘 revision 回退到旧版本。

EM 菜单及 F1 命令面板新增“合并恢复记录”，仅适用于已打开的桌面文件。选择恢复共同祖先、本地、磁盘或合并候选，指定父目录后生成独立的 `EasyM-recovered-<UUID>` 目录；再从 EM 菜单打开副本。不会覆盖当前文件。恢复列表也包含已归档但未提交的候选，记录存在不代表合并已经成功。

## 两阶段提交协议

前端继续以可靠的共同祖先 B、本地内存 L、本轮检查的磁盘 R 分析，不从历史猜基线。应用前检查文件身份、基线、B/L/R、文本修改计数、当前外部检查对象、活动标签和编辑/图片状态；归档完成后再次检查同一组见证，过期任务不能提交。

| 接口 | 输入与行为 | 结果 |
| --- | --- | --- |
| `prepare_merge` | 授权文件 id、B/R revision、B/L/R/候选的编码字节、AST 资源引用、允许的图片字节与实例元数据；校验当前 R，强制持久归档并回读验证，发布后再次检查 R | `operationId`、`recoveryPath` |
| `commit_merge` | 仅授权文件 id 和 operationId；从归档读取不可变候选，重新验证全部归档文件、图片路径冲突和磁盘 revision，通过现有资源/正文事务提交 | 新 revision、恢复目录、可能的提交后警告 |
| `merge_recovery` | 不带 operationId 时列出当前文件的记录；带 operationId/side 时由原生目录选择器授权恢复位置 | 记录及警告，或新副本路径；取消返回空 |

提交接口不接受另一份候选正文，避免“用户审查的候选”与“实际写盘的候选”不一致。资源引用复用现有 AST 扫描，大文档使用引用 Worker；原生层校验字节、格式、路径、图片与元数据，沿用历史接口的可信前端引用契约。

写盘成功后，前端一次 CodeMirror 补丁应用正文，更新磁盘快照和 revision，再清理对应草稿。若磁盘已提交而编辑器不能应用，暂停自动保存、保留本地编辑，并明确提示从恢复记录取回候选。模态窗口忙碌期间阻止重复提交和关闭；失败后焦点归还窗口，Escape/Tab 仍可用。

## 强制恢复归档与中断

恢复目录与可选的版本历史独立，位于文档旁的 `.easym/merges/<operationId>/`，即使用户未启用历史也必须先创建：

```text
record.json
base.md
local.md
disk.md
result.md
assets/...  # 受支持的新增图片源与显示副本
```

清单 `schemaVersion: 1` 保存 UUID、文档文件名、创建时间、B/R revision、每份正文/资源的名称、SHA-256 与大小，以及图片实例元数据。B/R 保存原始磁盘字节；L 按本地基线格式编码，未改动时保留原始字节，已编辑的混合换行正文用 LF；候选使用用户确认的格式。

新文件以 create-new 写入、同步并回读，完整校验暂存目录后 rename 发布。归档失败不写正文；归档发布后磁盘再变，保留归档并拒绝提交。正文提交复用现有操作日志、条件写入和暂存替换；正文已经提交后的图片元数据修复沿用既有重开恢复路径。中断前已发布的归档可在重新打开原文件后从“合并恢复记录”取回；未完成的暂存目录不是可恢复记录。

恢复先校验清单版本、四份正文、资源与路径，再在用户选择的父目录内暂存，最后发布到新目录。本地/候选副本带所归档的图片与实例元数据，B/R 在本步允许的范围内没有本地图片。任一校验失败都拒绝自动恢复，保留原记录和原文件。单文件损坏时用户仍可手工检查目录中其他原始正文。

归档是私有文档数据，不自动清理。一个文档目录共用 512 MiB / 128 项上限，扫描最多 20,000 条目；单份正文 10 MiB，单张图片 20 MiB，资源合计 128 MiB，最多 2,000 个资源文件和 1,000 个实例，并复用现有图像像素限制。配额已满会阻止新合并，提示先备份并手动整理。移动文档目录时应一并移动 `.easym/merges`；记录按文件名匹配，单独改名后不会自动关联旧记录，可手动从原目录取回。

## 图片与并发边界

**本步不提供完整的图片三方合并。** 旧文件会话没有打开时的图片字节见证，路径相同不能证明图片未被外部修改。按照冻结计划中“无法证明完整性则阻止应用”的规则：

- B 或 R 引用本地图片时阻止应用，即使用户选择删除相关文本或采用本地片段。提示另存本地副本后处理图片冲突。
- 存在未归档引用（例如上级目录的图片）、缺失源/显示字节或无完整实例元数据时同样阻止。
- 仅允许纯文本/远程图片链接，或 B/R 无本地图片而 L/候选有完整内存源、显示副本与实例元数据的新增图片。远程图片仅保留链接，不下载归档。
- 新增图片强制归档源与显示字节，检查 sourceHash、PNG/JPEG 格式与限额；同路径不同字节、同 displayPath 不同实例元数据均拒绝提交，不能由文字算法替用户决定。

revision 检查在归档前后以及现有事务最终替换前执行。它沿用项目的乐观并发保存机制，检查与文件替换之间仍有极窄的外部进程竞争窗口，不宣称提供操作系统级 compare-and-swap，也不提供多人协同锁。
