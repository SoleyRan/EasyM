# v0.3 第五步：批量图片与可访问性

日期：2026-10-13。基于第四步提交 `3f6c44e`，本步一次交付；应用版本仍为 0.2.0。本文件说明产品流程、数据契约、实现与验收范围，最终结果见 [可审查验收记录](verification/v0.3-step5-verification.json)。

## 1. 用户流程

EM 菜单增加“批量处理图片”。桌面已保存文档须先明确启用版本历史；未保存文档、浏览器模式、未启用或只读历史显示原因和引导。打开面板后锁定目标文档的编辑、自动保存与标签操作，关闭后恢复。

按 Markdown AST 列出当前正文的图片出现位置，保留 alt 和 title。共享引用定义的不同出现位置可分别选择；提交时仅将选中出现位置改为新的内联引用，其他引用、定义、正文和代码保持完整。远程、越界、缺失、不支持或损坏的图片禁选并显示原因。

选择最多 100 个实例，设置最大长边（1–8192，只缩小）、保持格式/PNG/JPEG、JPEG 质量（10–100）、去除元数据及可选背景色。透明图片转 JPEG 必须明确选择背景色，不能默默替换透明像素。质量控制传入实际编码器，与元数据选项独立。

“生成处理对照”按实例串行生成，显示进度，可取消。成功后显示真实生成的体积、尺寸和处理前后图片；修改参数或选择会作废旧候选。全部成功后由用户点击“确认整批应用并保存”，任何生成失败都不部分应用。提交期间不能取消已经派发的磁盘事务，关闭和 Esc 暂时禁用。

## 2. 元数据与图片基准

默认移除输出 PNG 的非像素附加块及 JPEG APP1–APP15/COM（保留解码必要的 Adobe APP14），保留像素和颜色解码必要块。取消移除时仅允许同格式 PNG 描述文本块和 JPEG COM 注释；EXIF/XMP/ICC/IPTC 或跨格式保留明确阻止，要求选择移除。画布已经解码方向并转换颜色，复制旧方向/配置可能导致二次旋转或颜色偏移，因此不承诺所有元数据原样保留。

该设置只影响处理后的显示副本。历史、原图片和本批次不可变基准仍保留原字节，不是清理整个目录的隐私工具，也不保证像素本身匿名。

本次读取当前显示副本，其原字节作为每个实例新的不可变源。新 recipe v1 只描述本批次的 resize/output，不重复执行上一实例的裁剪、旋转或翻转。批次日志记录之前的实例与参数；旧资源保留供历史、撤销、重做。回归覆盖 400×200 基准缩至 100×50 后再按原基准进行单图裁剪。

## 3. 边界与实现

| 层 | 责任 |
| --- | --- |
| `core/batch-images.ts`、`batch-options.ts` | AST 出现位置、参数/几何校验、引用补丁和相互重叠检查 |
| `core/image-metadata.ts` | PNG/JPEG 段检查、清理和受限保留 |
| `platform/batch-images.ts`、现有 history/image Worker | 长正文预检、资源去重、可取消后台编码、哈希、提交准备 |
| `BatchImageDialog.tsx` | 选择、参数、真实对照、焦点/播报、生成取消与明确提交 |
| `DocumentEditor.tsx` | 文档锁、前后资源清单、原生事务、一个撤销项、保存与草稿状态 |
| Rust `history.rs`、现有资源/正文事务 | 完整前快照、revision/字节/路径校验、批次日志、提交与重启后处理 |

最多扫描 4096 个引用、每批 100 个实例；去重输入最多 128 MiB，生成的各实例基准与显示副本合计最多 128 MiB，待保存资源含旧副本也不超过 128 MiB。单图 20 MiB、单边 8192、总像素 2400 万、正文 10 MiB 沿用现有约束。长正文引用分析在 Worker 中执行，10 秒超时并终止；图片生成沿用现有 Worker 超时与取消。保留旧副本可能先达到资源预算，提示另存并重新打开或缩小批次，不自动删除资源。

正文补丁在生成与提交前重新校验 AST 范围、原引用及非重叠关系。Rust 再校验 UTF-16 源范围（支持 emoji）、BOM/CRLF、补丁之外正文没有变化、实例元数据、图片格式与前后 SHA-256。检查磁盘正文 revision 和当前显示源字节，外部正文或图片已改动时阻止覆盖。混合换行须先由用户确认保存，批图不猜测转换。

没有新增依赖，没有增加生产 Worker 数量（仍为 5 个）；图片 worker 不加载 Markdown AST 解析器。

## 4. 保存、日志与故障

提交沿用同一文档写入队列，顺序为：校验 → 完整当前内存前快照 → prepared 批次日志 → 不可变资源/正文/图片元数据事务 → 批次结果快照及后处理状态。当前任何本地引用不能完整归档时禁止提交。配额或写入失败可能留下前快照/未引用对象，但不会将正文部分修改。

日志位于 `.easym/history/documents/<documentId>/batch-<operationId>.json`，schema 1，记录相对路径、选择项、前后哈希、旧实例、源范围补丁、选项、前快照、revision 和 started/failed/cancelled/prepared/committed/recovered 状态。每条日志最多 4 MiB，并计入历史预算；本步没有批次日志清理界面。日志不包含导入源的外部绝对路径。

正文提交后后处理失败返回“已保存、待恢复”的警告，不能声称回滚。重启/历史查询仅在当前磁盘正文哈希与批次 proposed 一致时补齐结果快照与状态；外部版本不匹配时保留日志，不自动覆盖正文。重复恢复不重复创建结果快照。复用现有资源事务恢复图片元数据。

编辑器以一个事务应用引用，可整批撤销/重做；资源保留而不重新编码。若磁盘已提交但编辑器补丁失败，暂停自动保存，明确提示重新加载或另存当前编辑。成功提交更新 revision、saved/dirty 与草稿；正常自动保存继续沿用既有历史策略。

历史/recipe/images schema 不变，历史新增原因 `batch`。旧应用可能拒绝修改不认识的新历史原因，但保留数据，应继续使用新版本。批次日志为独立新增格式。

## 5. 可访问性

批图对话框有可读名称、字段标签、禁用原因、状态播报、进度和焦点循环。生成时焦点移至取消按钮，提交时保持在对话框，Esc 不打断磁盘写入；关闭返回 EM。组合输入期间的 Esc 不提交或误关图片面板。

EM 菜单在触发按钮仍有焦点时支持方向键/Home/End，Style 子菜单支持左右键和 Esc。沿用标签可读名称及侧栏 separator 的键盘调整与 ARIA 宽度值。阅读模式将焦点移至退出按钮，Esc/按钮/原生全屏退出恢复原控件焦点，预览为只读。四主题检查批图面板焦点和文本，加入 `prefers-reduced-motion`。

自动化覆盖键盘语义和焦点，不代表完成 WCAG 2.2 AA 认证。Windows Narrator/NVDA、macOS VoiceOver、Linux 读屏及原生全屏/API 仍需各平台实机抽查。

## 6. 验收与下一步

最终本机结果：TypeScript/生产构建通过，31 个前端测试文件的 173 项测试通过，锁定依赖的 Windows Rust 50 项通过，统一生产回归（含性能）15 组全部通过。Windows Release 可执行文件重新构建，独立配置的原生窗口启动和正常关闭通过；这不等于原生功能全流程已验收。初次高并发测试与编译同时运行出现超时与连带失败，最终限制为两个测试 worker 后完整重跑通过，没有放宽断言。

本机 Windows 10.0.26200、Core 5 220H、31.7 GiB、Chromium 156.0.8078.4：100 个小图实例实际生成 3729 ms，帧间隔 p95 26.7 ms，Chromium 工作集采样峰值约 419 MiB（5 次样本，下界且共享页可能重复计数）。JPEG 质量 0.2/0.95 输出分别为 22,734/141,069 字节。既有 5 MiB 文本和 100 KiB 单行输入 p95 为 18.9/29 ms，均低于 50 ms 目标。四主题对照截图已人工查看。

本步增加核心/平台测试、Rust 文件系统故障测试与生产界面回归，统一入口 `verify:regression --performance` 包含批图。验证真实生产 image/history Worker、透明 JPEG、元数据、质量、共享多实例、失败/取消、冲突/配额、整批撤销/重做、单图继续编辑、持久化重载、100 张串行处理、键盘与四主题。桌面 IPC 的浏览器回归使用确定性夹具；实际落盘与阶段故障由 Rust 临时文件系统测试覆盖，不能把夹具当作原生对话框验收。

性能报告记录机器、浏览器、100 张 400×200 共享源缩至 100×50 的实际生成耗时、帧间隔和 Chromium 进程工作集采样。采样峰值是下界，共享页可能重复计数；不代表大照片集或原生 WebView 峰值保证。验证输出在忽略的 `test-results/`，可审查摘要和散列在本步验收 JSON。

尚待实机：原生文件对话框、真实大照片/低内存设备、外部应用竞争、读屏、macOS/Linux WebView 与 CI。未生成新安装包，未运行新的远程 CI，不复用旧包声明包含本功能。

下一步为第六步专用 PDF 引擎评估，比较现有系统打印、HTML 分页与结构化排版，形成采用/保留/延期结论；不在第五步直接引入 PDF 引擎。
