# EasyM v0.3 设计与实施计划

冻结日期：2026-10-12。开发分支：`feature/v0.3`。应用代码基线：`02c82a8`，第一步验收记录提交：`9ff528f`。本文冻结本轮最小交付范围、数据契约和实施顺序；功能状态以文末进度表与验证证据为准。

## 1. 阶段目标与范围

v0.3 是桌面办公增强阶段：把当前 Markdown 稳定导出为可继续编辑的 DOCX，提供跨会话版本恢复与差异查看，并建立可取消、可撤销的批量图片处理和主要操作的键盘路径。

| 交付 | v0.3 冻结范围 | 后续储备 |
| --- | --- | --- |
| DOCX | CommonMark/GFM 基础结构、PNG/JPEG、导出预检、固定办公样式、原生另存与浏览器下载 | DOCX 导入、自定义 Word 模板、修订/批注、公式和图表排版 |
| 本地历史 | 显式启用、完整快照、资源去重、跨会话查看、差异、恢复及另存副本 | 工作区备份包、历史全文搜索、自动三方合并、云历史 |
| 批量图片 | 当前文档选择实例、限制长边、PNG/JPEG 转换、JPEG 质量、去元数据、预览、取消和整批撤销 | 全工作区扫描、任意图片格式、智能压缩 |
| 可访问性 | 主要工作流键盘可达、对话框焦点、读屏名称、数值图片操作、减少动画和对比检查 | 快捷键重绑定、完整命令面板及正式符合性声明 |
| PDF | 保留系统打印，完成专用引擎的样例和分发成本评估 | 专用引擎集成、自动目录、公式/脚注分页 |

“差异”在本轮指当前文档与快照的只读对照、恢复前审查及图片清单对照。冲突继续保留现有外部版本重载与冲突副本流程；完整三方合并需要另行冻结共同祖先、合并 UI 和事务契约，不在本轮自动实现。

不新增账号、服务器、云同步、协作或插件运行时。DOCX/PDF 是交付格式，Markdown 原文仍是唯一可编辑正文。

## 2. 基线与通用约束

基线来源：[v0.2 设计](Easy-Markdown-v0.2-设计与实施计划.md)、[v0.2 交付](Easy-Markdown-v0.2-验收与交付.md)、[第一步实机记录](Easy-Markdown-v0.3-第一步-实机验收.md)。总体路线参考 [完整设计方案](Easy-Markdown-完整设计方案.md) 第 13、20、22 章。

- 使用同一个 CodeMirror 正文和撤销栈，保留源码、分屏、即时渲染与阅读模式。导出与查询历史不改变正文、文件身份、脏状态或撤销栈。
- 保留 UTF-8/BOM、CRLF/LF 以及未修改文件的原始字节。混合换行仍遵循现有明确确认规则。
- 图片仍是不可变资源；编辑和批处理生成副本，不改写用户源文件、导入原图或已有历史引用的字节。
- 原生路径通过已授权的文件/工作区身份解析。资源拒绝越界路径、符号链接逃逸、绝对路径和远程抓取；URL 解码后再校验。
- 不执行嵌入 HTML、MDX、代码块、模板表达式或文档中的指令。不上传正文、图片或诊断数据。
- 新的长任务使用任务身份、文档身份及正文版本检查；后台结果不得应用到已切换或已修改的标签。一次只对一个目标标签提交修改。
- 取消在提交前结束并清理临时数据；提交后报告已完成，不能把已经写入的结果称为取消。失败提示提供重试、取消或另存副本等可执行操作。

Windows 原生打开、图片预览、自动保存、重启后读取、HTML 导出已在第一步通过。真实 IME、PDF 保存/取消、完整图片/冲突流程、macOS/Linux GUI、签名及 macOS 许可缺项继续保留，不因开始 v0.3 变为通过。

## 4. DOCX 的用户流程

EM 菜单添加“导出 DOCX”。基于发起时当前标签的完整内存正文导出，包含未保存编辑，无需先保存 Markdown。新建草稿也可导出，输出建议名称是安全的文档名加 `.docx`。

1. 检查中文组合、图片编辑、保存/批量关闭等忙状态；不能开始时说明原因，不截断正在进行的操作。
2. 建立当前文档快照，后台解析，读取快照所引用的图片并预检。准备期间锁定目标文档修改、重载、关闭及改变资源的命令，其他标签保持可阅读；自动保存与导出任务串行协调。
3. 显示预检窗口：文件名、A4/Letter、默认/紧凑办公样式、警告数量和按源位置定位的明细。正常内容可直接导出；存在资源缺失时默认阻止确认，提供明确的“使用图片占位继续”选择。
4. 生成 DOCX。桌面使用原生保存对话框，浏览器模式下载 DOCX；退出预检、取消保存或生成失败均释放锁并恢复焦点。
5. 成功提示实际结果和降级警告，可返回正文处理警告。导出过程中不调用 `save_document`，不清除未保存草稿，也不写入 `.easym/images.json`。

“使用图片占位继续”只允许缺失、不支持或不授权的资源降级。超出输入/产物总量上限、结构生成错误和写入错误不能用这个选项绕过。超宽表格和不支持节点是可继续的格式警告；风险文本保留为静态原文。

### 4.1 结构映射

直接读取共享 Markdown AST，映射到独立导出模型；不从预览 DOM 或 HTML 推断 Word 结构。解析器必须提供未被预览处理改写的 AST：现有 `parseDocument` 会替换图片节点 URL，第 3A 步先提取公共解析入口，预览在自身树上注入属性，DOCX 在独立树上读取资源。

| Markdown 内容 | DOCX 表达 | 降级约定 |
| --- | --- | --- |
| 1–6 级标题 | 对应 Heading 样式，保留层级和文本 | 不自动生成目录 |
| 段落、中文、emoji、软/硬换行 | 原生段落与文本 run；软换行保留词间分隔，硬换行写显式换行 | 字形由办公软件及系统字体决定 |
| 加粗、斜体、删除线、行内代码 | 可组合的 run 属性 | 不把 Markdown 标记留在已支持文本两侧 |
| 链接/引用式链接、自动链接 | 安全的 http/https/mailto 外部超链接，保留标签 | 危险 scheme 和无法解析的内部锚点保留标签/地址并警告；不生成可执行链接 |
| 无序/有序及嵌套列表 | 编号定义与缩进；保留有序起始值 | 最多 9 层；更深层保留静态标号/缩进并警告 |
| GFM 任务列表 | 静态 `☐`/`☑` 与列表文字 | 不生成交互式 Word 表单控件 |
| 引用与嵌套引用 | 引用段落样式和缩进 | 复杂内部结构仍递归保留正文 |
| 围栏/缩进代码 | 等宽代码段落、浅底色、保留空格/换行，语言标注 | 本轮不做 DOCX 代码语法着色，不执行 Mermaid 等代码 |
| GFM 表格 | 原生 Word 表格、边框、表头重复、单元格段落和对齐 | 长表跨页；超过 8 列或单元格文本过长提示检查；不承诺自动最佳列宽 |
| PNG/JPEG，包括引用式和行内图片 | 嵌入媒体，使用当前显示副本；alt 写入图片说明 | 独立图片为单独段落；行内图片保持行内；缺图按预检选择占位 |
| 分隔线 | 段落分隔边框 | 无交互行为 |
| YAML/TOML front matter | 带标签的等宽原文区块 | 不解释为 Word 元数据，提示静态保留 |
| 原始 HTML、未知节点、未知扩展 | 按源范围显示静态原文区块 | 明确警告，不执行、不静默删除；公式作为普通文本或代码保留 |
| 链接定义 | 被引用时参与解析 | 未引用的定义按静态原文附录保留并提示 |

代码语言、公式、图表只影响本轮静态表达，不表示增加 Markdown 语法支持。嵌套样式、引用式资源、表格内强调/链接必须单独验证。未知节点的原文使用 AST 源范围截取，不能用对象序列化替代用户输入。

### 4.2 页面与字体

- 页面提供 A4 和 Letter，页边距四边 20 mm。正文以 11 pt、标题递减、代码 9 pt 为默认办公样式；紧凑样式减少段前段后与表格内边距，仍保持可读字号。
- 标题尽量与下一段同页；表格重复首行，普通表格行尽量不拆分；代码允许长行换行。超长单元格和代码可跨页，不承诺 Word/WPS/LibreOffice 分页完全相同。
- 图片按 96 dpi 换算显示尺寸，等比缩小到页面内容宽高内，不自动放大；最大边距和布局单位统一转换为 OOXML 单位。
- 字体指定常见西文/东亚字体族，但不捆绑、不嵌入商业字体。预检固定提示“字体和分页由目标软件决定”，字体缺失需要实机抽查，不能把未检测的字体替换标为已知事实。
- DOCX 风格独立于编辑器主题，深色/浅色主题都输出可阅读的办公文档；不增加任意 DOCX 模板上传或执行入口。

### 4.3 技术结构、依赖与限制

| 层/拟新增文件 | 职责 |
| --- | --- |
| `src/core/markdown-ast.ts`、`markdown.ts` | 独立原始 AST 入口与安全预览，保持图片定位和 source offset 契约 |
| `src/core/docx-model.ts` | AST 映射、结构/链接/未知节点预检，产出可序列化中间模型与警告 |
| `src/core/docx.ts` | 中间模型到 OOXML；页面、编号、表格、图片和字体样式 |
| `src/platform/docx-worker.ts`、`docx.ts` | 后台生成、超时/取消、资源加载、桌面保存/浏览器下载 |
| DOCX 预检组件及应用入口 | 文档任务锁、缺图选择、警告定位、焦点和进度 |
| `src-tauri/src/export.rs` | 新增独立二进制导出命令，原生另存、输出校验和原子写入 |

第 3A 步选定并精确锁定 npm `docx@9.10.0`（MIT），复用现有 TypeScript/Worker 工具链，不新增系统 Office、Pandoc 或浏览器运行时依赖。共享解析/模型/图片预检与候选库已在真实 Chromium Worker、应用 CSP 下运行；验证脚本复用 Vite 的 `worker` 条件导出，避免实体解码器依赖 DOM。示例生成通过中文、编号起始值、表格、图片原字节及 OOXML 检查，这只证明库/API 可用，尚不是产品完整导出实现。

传递依赖遵循已锁版本；JSZip 选择 MIT 许可，pako 同时保留 MIT 和 Zlib 文本，sax 保留 Blue Oak 1.0.0 文本。hash.js/isarray 的完整 MIT 文本和 pako 嵌套 Zlib 文本补入可追溯来源。Windows 清单/SBOM 已更新；其他平台仍需各自生成 Cargo 清单及原有人工许可复核。docx 声明 Node >=10，但 nanoid 6.0.2 要求 `^22 || ^24 || >=26`，开发使用 Node 22/24/26+，现有 CI Node 22 满足条件。候选验证构建约 570 KiB（含共享模型/解析器）；后续通过按需 Worker 接入，不将其放入启动主包。

导出模型版本为 1，警告包含 `code`、中文说明、严重性（可降级/信息）、源范围和可选资源路径。缺图/受限图片默认阻断，明确选择占位才可继续；配额通过不可降级的 `quota_exceeded` 错误阻断。代码包括缺图、受限图片、未知节点、危险链接和超宽表格。诊断路径只用于当前应用，不把本机绝对路径写进输出文档。预检结构和资源字节分离，不修改输入树或模型；重试从当前正文重建，不累积旧缺图警告。

限制冻结为：Markdown 按 UTF-8 计最多 10 MiB；单图 20 MiB、单边 8192、总像素 2400 万；去重后的图片最多 128 MiB；最终 DOCX 最多 192 MiB。最多 500 张去重图片、100,000 个 AST 节点，最多 1000 条详细警告（其余给总计）。解析前校验文本量，解析后迭代校验节点数，再递归映射，不能仅依赖最终 ZIP 压缩后的大小。

3A 补充：AST 总深度最多 128（根深度为 0），避免递归映射耗尽调用栈；这只限制导出，不限制正文保存，也不改变 Markdown 格式。PNG/JPEG 读取同时要求安全本地相对路径和 `.png`/`.jpg`/`.jpeg` 扩展名，复用 HTML 的路径规则，拒绝 URL、绝对路径、编码穿越及 SVG。3A 仅验证图片头与尺寸；3B 平台预检已接入完整解码、授权读取、60 秒生产任务超时、输出配额及保存事务。核心预检仍允许注入解码器供无 DOM 单测使用，界面必须调用平台预检接口。

解析和生成分别设置 60 秒超时；资源加载有取消检查和总量检查，默认串行加载、及时释放中间字节，不无限并发解码。具体内存峰值在第 3C 步记录，达到大小上限不等于承诺所有机器都能顺畅导出。

新二进制导出仅接受 `.docx`，限制字节长度并核验 ZIP/必要 OOXML 项。原生保存对话框直接授权输出路径；拒绝打开中的文件、目录和符号链接目标。同目录临时文件写入、同步、替换；写入失败保留已有目标。覆写由原生对话框确认，并在写入前复核目标，发现竞争返回冲突，不默默覆盖后来出现的外部版本。不加入 Markdown 会话，也不接受从正文传来的任意磁盘路径。

3B 保存校验使用锁定的 Rust `zip@6.0.0`（MIT，仅 DEFLATE）和既有 `quick-xml@0.42.0`（MIT），`same-file@1.0.6` 复核打开文件的硬链接身份。ZIP 条目最多 4096、总解压量最多 192 MiB、XML 深度最多 128；这保护原生解压内存，不改变 Markdown/图片格式，触限返回不可降级的配额错误。CRC、必要项/根命名空间、XML 结构和无 DTD/宏/OLE/外部图片关系一并检查。目标 SHA-256 在对话框返回及临时文件同步后复核；新目标使用不可覆写提交。该协议检测到的外部改动会阻止保存，但现有目标的最终复核与原子替换之间仍有极短竞争窗口，不能作为对任意外部进程的文件锁保证。3C/跨平台实机应检查原生对话框覆写/取消和受占用目标行为。

## 5. 持久快照与差异

### 5.1 启用、身份和存储

本轮为桌面本地能力。EM 菜单添加“版本历史”，首次说明历史位于文档目录的 `.easym/history/`，会包含正文与图片，随目录复制可能一起分享；用户显式启用后才建立历史。未保存草稿继续使用现有 IndexedDB 恢复，提示先保存文件以启用持久历史；浏览器模式显示能力限制。

当前原生 `fileId` 是进程内授权令牌，不能直接作为跨会话历史身份。新增 UUID `documentId`，在文档父目录的历史索引中与规范化相对文档路径绑定。同目录重启复用该身份；另存为建立新身份，可记录来源快照但不把两文件绑定到同一条可写时间线。外部移动/重命名先视为新路径，由用户明确选择重新关联历史，不通过内容相似度自动认领。

历史 schema 为 1，与现有 `.easym/images.json` schema 1 分离，旧文件未启用时无需迁移；未知重大版本只读提示并保留原数据。

```text
.easym/history/
  index.json
  documents/<documentId>/snapshots/<snapshotId>.json
  objects/<sha256-hex>
```

`index.json` 保存 schemaVersion、相对文件路径到 documentId 的映射和启用/保留配置。快照清单记录 schemaVersion、snapshotId、documentId、parentSnapshotId、时间、原因、可选名称、正文对象哈希、字节数、encoding/lineEnding、diskRevision、图片资源清单和图片实例/recipe 元数据。资源项包括安全相对路径、对象哈希、大小、MIME、角色（原始/显示/普通引用）、缺失状态；对象文件保存原始字节，以 SHA-256 去重并读取时复核。

diskRevision 基于真实落盘字节，不以规范化文本替代。parentSnapshotId 只表示本地历史链，不能冒充外部修改的共同祖先。每个历史目录必须验证身份字段、大小、相对路径和符号链接，历史 JSON 也视为不可信文件。

### 5.2 触发、资源和事务

- 启用时捕获当前磁盘基线；手动“创建快照”可捕获内存编辑，记录其 base diskRevision，保留当前文本的实际编码策略。
- 首次保存、批量图片提交前、版本恢复前建立重要快照；成功普通保存创建自动快照，同正文与资源哈希不重复，自动快照至少间隔 60 秒。本轮不承诺保存每次按键或每个自动保存版本。
- 快照包含正文所引用的授权 PNG/JPEG、已知图片实例的原始/显示副本和参数。外部图片缺失时保留正文并标记不完整；已归档对象不依赖原 `assets/` 继续存在。不能仅存路径却称为完整图片恢复。
- 先写入/校验不可变对象，再原子写入快照清单，最后更新索引。中断产生的未引用对象不会污染已完成快照，可在明确清理时回收；启动后核对索引并修复完成的清单关联，不自动替换正文。
- 普通自动保存的历史失败提示“正文已保存，版本快照未完成”，不破坏现有可靠保存。恢复/批图等明确要求保留前版本的操作，若前快照失败则在正文提交前停止；用户仍可另存副本。

历史与现有资源提交日志必须按同一文档写入队列协调。清单写入成功不表示正文保存成功，两项分别记录结果；正文写入后发生后处理错误遵循既有“已提交、待恢复”提示。

### 5.3 查询、差异和恢复

版本面板显示时间、原因、名称、完整性和资源体积，支持手动命名/固定、选中预览、与当前版本对照、恢复、另存副本。查询历史不触发保存。差异默认按行显示新增/删除和上下文；换行/BOM 的字节差异额外标注，不把 CRLF 显示变化伪装成整篇正文修改。

比较输入最多各 5 MiB/100,000 行，在 Worker 中执行、可取消；超出或计算超过 10 秒时改为双方只读全文查看并提示未生成逐行差异。图片按引用、实例和哈希标注新增/删除/变更，支持已归档显示副本缩略图；不把正文图片路径差异直接等同于像素差异。

“恢复”先显示差异并明确确认，检查当前文档 revision；保留当前版本的前快照，再把目标正文和资源作为一个编辑事务应用，使用现有保存事务提交，产生新的历史版本。当前状态存在外部冲突时阻止覆盖并提供另存副本。目标资源重新落盘为不可变副本，遇到同路径不同字节不覆盖，重定位 Markdown 引用和实例路径。

恢复替换正文只生成一个撤销项，当前文件保持自己的编码/换行规则；若需要目标原始字节完全一致，使用“另存副本”。混合换行或无法安全映射资源时明确提示，不直接猜测。未知历史 schema、哈希损坏或缺失关键资源默认阻止恢复；用户可选择仅另存正文并带缺图说明。

取消预览/另存对话框不改当前正文。恢复提交失败时保留当前数据、候选快照与恢复日志；保存失败不能清除脏状态或历史。

### 5.4 保留与清理

默认保留自动快照 30 天、每文档最多 100 个自动快照，手动/固定/恢复前快照不在自动淘汰集合。每个文档目录的历史预算默认 512 MiB。达到预算后暂停新增快照并给出清理/提高配额入口，不删除当前正文、图片或草稿来腾空间。

本轮清理为显式操作：先列出拟删除快照与估算可释放空间，确认后提交索引变更，再只回收该历史目录中无任何保留快照引用的对象。中断可重试，固定快照默认不删；不扫描或删除 `assets/`、其他目录历史、分享资源或 IndexedDB 草稿。历史是本机恢复能力，不等同于设备备份。

## 6. 批量图片处理

EM 菜单添加“批量处理图片”，本轮作用于桌面已保存并启用历史的当前文档；未满足条件时引导先保存/启用历史，以便提交前保留完整前版本。处理对象是已解析的图片实例；同图多次插入可单独选择，未授权、远程、缺失图片列出原因并禁用。一次最多 100 个实例，输入去重资源总量最多 128 MiB，单图/像素限制沿用第 4.3 节。整工作区批处理与浏览器持久批次恢复留待后续。

处理选项包括：最大长边（仅缩小）、保留格式/PNG/JPEG、JPEG 质量、去除元数据。透明图转 JPEG 必须选择背景色；隐私去元数据和质量压缩分开说明。JPEG 质量作为编码选项存入批次记录；沿用图片 recipe v1 的几何和 output 字段，不为本轮编码选项改写旧 recipe schema。

预检展示实例、原/预计尺寸、原体积、选项和异常；预计体积必须来自实际生成的样本，不用公式伪装准确大小。允许查看原图/处理副本对照，清楚显示重新编码后的视觉与元数据检查范围；不声称仅凭扩展名就去除了隐私元数据。

处理器读取当前显示副本，将其字节复制为本批次不可变基准源，再应用限制长边与重新编码；旧导入副本和已有 recipe 保留在前快照与批次日志中。当前实例的 sourcePath/sourceHash 指向本批次基准，recipe v1 以其尺寸为基准，仅记录本批次的 resize/output，不重复执行旧裁剪/旋转。批次日志记录来源链和编码参数。后续单图编辑需基于正确源几何，不把调整尺寸后的 recipe 套到错误大小的源上；该组合在第 5A 步建立回归样例。

任务串行或有界队列生成资源，逐项报告进度，提交前锁定目标正文与实例；按源范围倒序更新引用，先校验任务正文 revision 和实例引用仍一致。所有选定项成功且新资源通过校验后，以单个编辑事务提交正文、实例和待保存资源，复用现有文件/元数据恢复日志。任一项失败或提交前取消，整批保持原文并清理未引用临时资源，提供重试；本轮不提供静默部分成功。

提交后一次撤销恢复所有引用和实例；重做再次使用已生成不可变字节，不重复压缩。已落盘副本不在撤销时立即删除，因为历史或重做可能引用。外部 revision 冲突不覆盖文件，保留当前编辑与草稿并走现有冲突副本路径。批次日志记录任务 ID、选项、实例、前后哈希、成功/失败/取消和提交状态，不记录用户外部源文件的绝对路径。

## 7. 可访问性与桌面交互

保留 EM 菜单、自定义窗口按钮、可隐藏格式栏、标签、侧栏和阅读模式。新增面板使用与主题一致的组件，不额外增加常驻工具栏占用编辑空间。

| 工作流 | 冻结验收要求 |
| --- | --- |
| EM 菜单/导出预检 | 键盘打开、方向键选择、Enter 执行、Esc 关闭；对话框焦点循环，关闭返回触发控件 |
| 标签与侧栏 | 可定位当前项，关闭/切换有可读名称；侧栏宽度有键盘调整路径和合理最小值 |

| 编辑器/格式命令 | 工具栏保持正文选区、按钮状态反映格式；组合输入期间不提交格式/视图切换 |

## 9. 验收样例与门槛

固定语料位于 [v0.3 样例说明](samples/v0.3/README.md)，包含 [办公导出](samples/v0.3/办公导出.md) 和 [降级与安全](samples/v0.3/降级与安全.md)。样例正文是输入，验证程序不能先把不支持内容删掉以获得通过。后续输出 DOCX/PDF、截图和临时历史放入忽略的 `test-results/`；仓库只保存样例、可审查报告与必要静态资源。

### 9.1 DOCX

- 解压 ZIP 检查必需 OOXML 项、合法 XML、段落/标题层级、编号起始值/嵌套、表格行列及重复表头、图片字节和 relationships。
- 输出无宏、脚本、OLE、远程媒体关系和危险超链接；仅用户文本里的普通 URL 不作为自动资源请求。PNG/JPEG 的嵌入内容必须与选定显示副本匹配。
- 未知节点、HTML、front matter、引用资源和缺图有可定位预检；取消和失败保留标签、正文、dirty、草稿及撤销。桌面和浏览器保存路径分别验证。
- Microsoft Word、LibreOffice 和一个明确版本的 WPS 中记录打开、中文/图片/表格/代码、分页和编辑可用性。自动结构检查通过不代替这些排版检查；字体差异可接受，缺字、内容丢失、图片裁掉或损坏文件阻断交付。

### 9.2 历史与批图

- 重启、重命名、另存、同内容不同文件、目录含空格/中文及历史 schema 未知时，身份不混用。
- BOM/CRLF、资源去重、原始/显示副本、缺图与哈希损坏均有样例；删除当前显示文件后仍可从完整快照另存恢复。
- 在写对象、写清单、更新索引、正文提交和元数据提交处注入故障；当前文件保持完整，已提交阶段可恢复，不能虚报回滚。
- 差异取消/超时/上限、当前 revision 变化、恢复失败、外部冲突、资源重定位、历史清理和固定快照保护均覆盖。
- 批图包含透明 PNG、JPEG 元数据、同图多实例、缩小后继续单图编辑、失败/取消、撤销/重做、自动保存及重启恢复；原始资源 SHA-256 不变。

### 9.3 全量交付

各子步骤运行针对性单测/契约/生产界面检查；原生文件修改运行 Rust 相关测试。收尾运行 `pnpm.cmd typecheck`、`test`、`build`、`verify:workers`、统一 `verify:regression --performance`，以及锁定依赖的 Rust 测试与三平台 CI。新增功能验证纳入统一入口，不移除 v0.1/v0.2 断言。

性能沿用 5 MiB 文本、100 KiB 单行、100 张图片基线，输入 p95 50 ms 为目标；另记录 DOCX/差异/批图时间和峰值内存。长任务不能导致正文丢失或无法取消；数值结论标明系统、WebView 和样例规模。

依赖变更同步精确锁文件、第三方清单、完整许可文本与 SBOM。Windows 包、源码提交、前端/可执行文件与锁文件散列关联；不得覆盖历史证据后声称旧包含新功能。三平台实机、办公软件排版、读屏、签名和许可人工复核列明执行方与状态。
