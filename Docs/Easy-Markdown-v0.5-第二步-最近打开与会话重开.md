# EasyM v0.5 第二步：最近打开与会话重开

日期：2026-10-14。分支 `feature/v0.5`，基线 `db89561`。产品版本仍为 `0.4.0`。

## 用户行为

EM 菜单和命令面板新增“最近打开”。按最近成功打开/保存的顺序展示最多 30 个文件和 10 个工作区，显示完整位置区分同名项。支持移除单条、清空记录，操作只改变登记信息，不删除文件、草稿、资源或历史。浏览器禁用原生最近打开，不伪装持久磁盘权限。

启动恢复标签顺序、活动标签、工作区及最多 20 个没有独立草稿的已保存文件，超出时提示通过最近打开访问。有草稿的目标优先显示独立恢复副本，不重开旧进程文件 ID、不自动写回磁盘；仍可从最近打开显式打开原磁盘版本。失败项提示后跳过，其他标签照常恢复。已打开文件按当前原生句柄复用，保留内存修改及撤销栈。

最近打开面板使用既有模态浮层与焦点规则，读取中和操作中禁止重复操作；允许完成/Escape 取消未完成的文件打开。迟到结果不改变当前标签，只释放无人使用的新句柄，不能释放其他标签正在使用的句柄。

## 实现与数据契约

新增原生 `recent.rs`，在 `app_data_dir()/recent-v1.json` 保存版本 1 的 `{version, records, session}`。`records` 使用 UUID、类型、规范化路径、可选工作区边界；以有界 MRU 数组排序。`session` 为 `{tabs:[{draftKey,recentId}],activeDraftKey,workspaceId}`，最多 100 项，不保存正文、图片、旧原生句柄。前端独立草稿及第一步 localStorage 索引不迁移，完整路径仅由原生保存；前端只能用记录 ID 请求重开。

读取最多 1 MiB，校验版本、字段、数量、重复 ID/路径、绝对路径和工作区边界。未知版本、损坏记录保留原文件并拒绝覆盖。写入同目录临时文件、同步后替换；写入失败返回提示，不回滚已成功写入的 Markdown 或清理草稿。

文件/工作区选择器授权后、授权工作区内成功打开文件后、原生保存成功后登记。重开逐级检查规范路径与符号链接/目录替换、类型、扩展名、10 MiB 文本上限及读取权限，再通过既有打开路径获取当前进程新句柄。工作区沿用现有目录遍历限制。记录不是任意路径打开接口，移除记录后不能用旧记录 ID 打开。

原生目录登记和磁盘 IO 在阻塞任务中执行；启动恢复串行且在编辑器挂载前完成。前端会话布局按 150 ms 去抖串行保存，正常退出补写当前最终布局；保存布局失败保留旧记录，不阻止正文和草稿保存。关闭决策期间停止旧的定时布局写入，避免旧快照覆盖退出时状态。

## 验证

新增应用测试覆盖新句柄重开、草稿优先、工作区、失效文件隔离、未知原生记录保留、复用内存编辑及取消释放；恢复规划测试覆盖 20 个已保存文件上限和独立草稿不丢失。

Rust 新增持久记录/中文同名/新进程身份/移除保留正文、30/10 项上限、损坏/未来/超限文件保护、写入失败、删除/目录替换/超限目标和伪造边界测试；Unix 另含文件/父目录符号链接替换测试，需由 Linux/macOS CI 执行，本机 Windows 不宣称通过该项。

新增 `pnpm verify:recent`，以真实生产 Chromium、CodeMirror、IndexedDB 和受控原生 IPC 验证菜单、自动保存、重开/复用、刷新后草稿与磁盘分离、工作区、删除记录、异步取消及焦点返回。既有原生 IPC fixture 补充空最近记录及会话写入响应，不削弱原有业务断言。接入全量生产回归和 CI 产物收集。

本机 44 文件 / 244 项前端单测、最终启动调整后的 67 项针对性单测、Windows Rust 61 项测试、22 组生产回归、类型检查/构建及版本元数据核验均通过。最终结果见 [验收汇总](verification/v0.5/step-2/summary.json)；真实系统选择器、权限撤销、原生异常退出、macOS/Linux GUI 与当前提交远端 CI 待对应设备或推送后验证。未打新安装包，未新增运行时依赖，未修改许可清单。第三步才实现主动外部变更检测和冲突对照。
