# EasyM v0.7 设计与实施计划

冻结日期：2026-10-16。分支 `feature/v0.7`，从已合并 v0.6 与 CI 修复的 `main` 提交 `36b8163` 创建。按四步开发，每步验证并记录后再继续。前三步保持产品版本 `0.6.0`，交付时统一升级为 `0.7.0`。

## 目标与边界

沿总设计“可靠保存 → 持久快照 → 冲突合并”的顺序，补齐桌面数据保护：让外部修改可审查、可合并，并提供可携带的文档备份恢复。Markdown 仍是唯一正文，保留现有图片实例、编码/BOM/换行、草稿及条件写入契约。

不加入账号、网络同步、多人协作、插件、AI、DOCX 导入、新语法或专用 PDF 引擎。仅借鉴 MarkText 的交互设计，不引入其代码、资源或文案。已有 IME、读屏、跨平台 GUI、签名和 macOS 许可全文等门槛继续单独记录，启动新版本不表示这些验收已经通过。

## 第1步：共同祖先与只读合并分析

- B 是当前标签最后一次成功打开/保存的 `FileSnapshot.originalText`，并须有对应的磁盘 revision；L 是当前内存正文，R 是本次检查得到的磁盘正文。不能用“最接近的历史快照”猜祖先；找不到可靠 B 时只提供原有比较/另存副本。
- 独立实现保守的逐行三方合并。在不同基线行上的改动可组合；相同改动只保留一次；同一位置的不同插入、交叠修改/删除及删除范围边界的插入进入冲突。相邻但不交叠的行修改可以组合。同一行不同字符首步仍属于冲突，不做语义或字符级猜测。
- 不注入 `<<<<<<<` 等冲突标记。分析结构明确区分普通内容和未解决冲突，只有零冲突结果才提供完整候选正文；保留末尾换行、空行、Unicode 和 Markdown 字面内容。
- 分析复用现有后台差异 Worker。每份输入最多 5 MiB / 100,000 行，共享约 9.5 秒计算期限，现有差异轨迹最多 2,000,000 单元；超过 2,000 个改动区域或结果超过 10 MiB 时回退全文比较。宿主 10 秒超时终止 Worker，关闭弹窗/输入变化取消旧任务，不应用过期结果。
- 外部版本比较中增加按需“分析三方合并”，展示是否可合并、只读候选或 B/L/R 冲突片段。本步不应用候选，不写文件、不切换基线、不创建快照，自动保存继续暂停。界面限制冲突展示数量与片段长度，双方全文仍可选择复制。
- 验收：独立/交叠/相邻改动、相同插入、删除对修改、空正文/末尾换行、重复行、中文/emoji、交换 L/R 对称性、输入/期限/区域限制、取消/失败/过期结果及生产 Worker/UI。保留原有外部比较与重载保护。

## 第2步：冲突选择与安全应用

在第1步分析上加入逐块选择本地/磁盘及手工结果、完整候选审查与显式应用；未解决项不允许提交。应用前重新检查标签身份、B/L/R 和磁盘 revision，任一变化则作废重算。保留双方正文与资源，再用既有条件写入和原子资源事务提交；操作失败或磁盘再次变化不得覆盖任一方。

合并前持久保存可恢复的双方版本，不能依赖用户已启用普通历史；归档失败阻止应用。图片资源/实例冲突不得由正文算法推断解决，缺失、同路径不同内容或无法证明完整性时阻止应用并引导另存。编码/BOM/换行变化单独确认，混合换行沿用显式转换保护。合并作为一次编辑事务，撤销只恢复本地内容，不撤销对磁盘的安全检查；恢复旧正文后仍按当前磁盘基线条件保存。

本步需一并冻结前后端协议、恢复记录和中断恢复路径，再接入写操作；不是简单把 R 的 revision 赋给 L 后保存。

第2步实施冻结：使用 `prepare_merge` → `commit_merge` 两阶段协议，先强制归档 B/L/R/候选及支持的新增图片到文档旁 `.easym/merges/<UUID>/`，再按不可变 operationId 提交。EM“合并恢复记录”可将四种版本恢复到新目录，候选记录不代表提交成功。旧文件会话缺少原有图片的字节见证，因此 B/R 含本地图片或任一引用无法归档时阻止应用；只允许纯文本/远程链接及完整内存资源的本地新增图片。具体协议、限额、中断路径和验收见 [第2步记录](Easy-Markdown-v0.7-第二步-冲突选择与安全应用.md)。

## 第3步：可携带备份与恢复

先提供当前文档备份包：精确 Markdown 字节、所引用/托管的图片源与显示副本、实例元数据、版本化清单和逐文件校验；可显式选择包含该文档历史。说明备份范围，不把单文档包称为整个工作区备份，不自动纳入其他文件、最近路径或凭据。

恢复到用户选择的新目录，预检版本、哈希、资源完整性、路径和解压限额；拒绝路径穿越、重复/大小写冲突条目、符号链接和解压炸弹。暂存校验完成后提交，不覆盖已有文档或把包内绝对路径当权限。失败/取消可清理暂存并保留原包，未知新版格式只读拒绝恢复。包含历史时保留版权/格式契约且不能把备份中的路径配置直接应用到本机。完整工作区备份与增量/定时备份不在本轮。

## 第4步：验收、帮助与交付

补齐三方合并/备份样例、导引及恢复说明；升级为 `0.7.0`，核对许可/SBOM变化。运行前端测试、生产回归、性能、涉及原生层的 Rust 与三平台 CI，检查 Windows 原生启动/隔离安装/便携包并生成开发安装包。分别记录功能完成、自动检查和人工/发行门槛。
