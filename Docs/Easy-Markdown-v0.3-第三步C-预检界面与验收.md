# v0.3 第三步 C：DOCX 预检界面与验收

本步承接 `3bca0a3 feat(docx): generate and safely save office documents`，完成 EM 菜单到预检、生成、保存的界面闭环，以及生产浏览器和 Microsoft Word 验证。应用版本仍为 0.2.0，没有生成新安装包。本步改动尚未提交；WPS、LibreOffice 和原生保存对话框实机项目仍待验收，不能据此声明整个 v0.3 已完成。

## 界面与正文保护

- EM 菜单新增“导出 DOCX”。从当前内存正文创建快照，包含未保存编辑；动态加载 DOCX 模块和内联 Worker，不在应用启动时加载这部分代码。
- 对话框提供 A4/Letter、默认/紧凑办公样式，显示文件名、预检提示总数、资源路径和行列定位。长路径换行，警告列表滚动，支持四种现有主题。定位按钮取消本次导出并返回正文位置。
- 缺失、无效或远程图片默认阻止生成，只有勾选“使用图片占位继续”才允许降级。硬配额与超时仍然失败，不能由占位绕过。输出使用当前显示副本，不改写资源或原 Markdown。
- 预检、生成可用取消按钮或 Esc 中止；迟到结果不能影响新任务。派发原生保存之后禁用取消，Esc 不会虚报中止已交给原生端的写入；保存对话框自行决定取消或确认。
- 对目标文档锁定编辑、资源更改、重载和关闭，等待已开始的自动保存完成后才能导出，导出期间暂停该文档自动保存。导出不调用 `save_document`，不清 dirty、草稿、撤销/重做或图片操作。成功、取消、失败后释放锁，可再次导出。
- 预检或生成期间，已有其他标签时提供“阅读其他文档”。后台任务继续，返回目标标签显示当前阶段；其他标签可阅读，目标仍锁定，关闭所有/窗口不能绕过忙状态。后台完成不会抢走其他标签焦点。
- 对话框有可读名称、状态播报、Tab/Shift+Tab 循环和阶段焦点恢复；Esc 忽略组合输入。关闭返回 EM，定位返回正文。仅在活动目标标签挂载键盘监听，避免隐藏导出任务拦截其他标签的 Esc。

## 自动化验证

`pnpm.cmd verify:docx-ui` 使用生产构建、真实导出 Worker、真实 PNG 导入与浏览器下载，验证未保存正文、纸张/样式、缺图确认、警告定位、取消、失败、焦点、目标锁、其他标签阅读、dirty/撤销、草稿与重载恢复、四主题和大文档。故障通过不响应/失败 Worker 注入，不替换正常生成路径。完整源由草稿读取核对，避免把 CodeMirror 虚拟化 DOM 当作全文。

该入口纳入 `verify:regression`，CI 保存报告及界面截图。生产 Worker 检查现要求 Markdown、图片、搜索、DOCX 各一个，逐个验证无 DOM 初始化并检查 DOCX 模型解析；图片验收按 Worker 类型选择，避免误选同样包含图片解码的 DOCX Worker。旧功能断言保留。

本机 Microsoft Word 16.0.20430.20146。`scripts/verify-docx-word.ps1` 创建独立隐藏 COM 实例，禁用宏，仅打开测试产物：

| 样例 | 页数 | 表格 | 内联图片 | 打开及编辑后重新打开 |
| --- | --- | --- | --- | --- |
| Letter/紧凑办公 | 1 | 1 | 0 | 通过 |
| 缺图占位 | 1 | 0 | 0 | 通过 |
| 当前显示图片 | 1 | 0 | 1 | 通过 |
| 冻结办公样例 | 2 | 1 | 2 | 通过 |

另存副本末尾插入验证文字后保存并重新打开；原测试输出保留。Word 导出 PDF 后使用 Poppler 渲染：办公样例两页逐页检查，长样例 25 页总览并放大检查第 15、19、23 页，分别覆盖重复表头、长代码、图片。抽查未发现中文/emoji 缺字、内容裁切、表格边框缺失或意外空白页，代码保留缩进，图片比例正确。四主题界面截图也已目视检查。上述为固定样例结果，不承诺任意复杂文档或其他办公软件分页一致。

可复现命令（Word 检查仅 Windows 且需已安装 Word，不纳入 Linux CI）：

```powershell
pnpm.cmd build
pnpm.cmd verify:docx-ui
./scripts/verify-docx-word.ps1
pnpm.cmd verify:regression
```

## 性能与剩余验收

大样例为 3,652,113 字节 UTF-8 正文、140,000 次正文句和 100 次图片引用；检查全部正文与图片节点均进入输出。使用 Windows 10.0.26200、Intel Core 5 220H、16 逻辑核心、31.7 GiB 内存及 Chromium 156.0.8078.4，预检、生成下载时长与内存数值记录在验证 JSON。它是本机基线，不是支持上限或最低配置承诺。

内存为专用浏览器进程树的 RSS/Windows working set 总和，包括渲染器与 Worker；共享页可能重复计数，采样峰值是下界。循环设定 500 ms 间隔，加上查询耗时，实际周期更长，不能解释为精确瞬时堆内存。没有读取用户日常浏览器配置或草稿。

剩余项目：WPS/LibreOffice 明确版本的打开、分页和编辑；桌面原生另存对话框的覆写/取消及受占用目标；macOS/Linux GUI；真实读屏和输入法；最终打包与三平台 CI。原生保存事务的文件竞争/失败保护已有 3B 契约测试，但不能替代对话框实机检查。后续第四步整体完成持久历史、差异和恢复，办公软件缺口继续保留在交付清单。
