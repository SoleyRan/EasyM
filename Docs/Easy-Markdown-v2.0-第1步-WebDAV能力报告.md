# EasyM v2.0 第 1 步：WebDAV 能力报告

日期：2026-10-20 至 10-21。分支：`feature/v2.0-step-1-webdav`，从 main `058a994` 创建。

结论：原“全局头指针 + 条件更新”在两个服务上都不可靠。改用每设备单写者日志后，Apache 2.4.69 与 Nextcloud 31.0.14 均通过全部 16 项检查。冻结支持清单为下表两个固定版本，Provider 为 WebDAV（每设备日志）。

## 1. 环境与范围

| 项 | 版本 / 设置 |
| --- | --- |
| Apache httpd mod_dav_fs | 2.4.69，`httpd@sha256:c842ac79…6785a`，FileETag MTime Size |
| Nextcloud | 31.0.14（apache 镜像 `sha256:07ec73cc…3767`），MariaDB 11.4.13，Redis 7.4.11（事务文件锁） |
| 宿主 | Windows 11 26200，Docker Engine 29.6.2 / Compose v5.3.1（WSL2），Node.js v24.20.0 |

容器仅绑定 127.0.0.1，HTTP 明文、Basic 认证；随机凭据保存在被忽略的 `test-results/v2.0/step-1/`，每次运行使用新的 workspaceId 命名空间。结果只代表上述固定版本的回环环境，不代表 TLS、反向代理、外部网络、其他存储后端或其他版本。

## 2. 第一轮：全局头指针条件更新（已放弃）

证据：[head-cas-report.json](verification/v2.0/step-1/head-cas-report.json)。

| 检查 | Apache | Nextcloud |
| --- | --- | --- |
| 首次创建竞争（10 轮 × 8 客户端）仅一个 2xx | 失败：8/10 轮多个 201 | 失败：1/10 轮 201+204 |
| If-Match 竞争（20 轮 × 8 客户端）仅一个 2xx | 失败：13/20 轮多个 204 | 通过 |
| If-Match 竞争每轮有进展 | 通过 | 失败：3/20 轮全部 423 Locked |
| 其余 16 项（凭据、对象防覆盖、强 ETag、响应丢失、取消、写后读等） | 通过 | 通过 |

“多个 2xx”指服务对同一基线的多个条件写都回复成功，只保留最后一个，其余被确认的提交静默消失。补充原语测量见 [primitive-probes.txt](verification/v2.0/step-1/primitive-probes.txt)，探针位于 `scripts/webdav/probes/`：

| 原语 | Apache | Nextcloud |
| --- | --- | --- |
| 同基线 If-Match，2 客户端 × 50 轮 | 50/50 轮双方均 204 | 无多重成功；23–33/50 轮双方 423 |
| If-None-Match:* 创建，50 轮 | 2 客户端：50/50 轮双方均 201 | 2 客户端 1/50、8 客户端 9/50 轮多个 2xx |
| MKCOL 同名集合，16 客户端 × 100 轮 | 每轮恰一个 201 | 每轮至多一个 201；6 轮全部 423 |
| MOVE Overwrite:F，8 客户端 × 30 轮 | 27/30 轮多个 201 | 无多重成功；124 次 500 |
| 排他 LOCK | 13/30 轮多个持锁者 | 不支持（501） |
| 唯一名称 PUT + PROPFIND 列表（240 项） | 全部可见 | 全部可见 |

## 3. 第二轮：每设备单写者日志

参考同类应用（Joplin、Remotely Save 等均不依赖 WebDAV 原子写入）后，改为每台设备只写 `devices/<deviceId>.json`，内容对象仍按摘要不可变存放，设备间通过确定性合并收敛。设计见 [RFC 第 4 节](Easy-Markdown-v2.0-第0步-RFC.md#4-最小远端协议)，实现见 `src/core/sync-log.ts`。证据：[webdav-report.json](verification/v2.0/step-1/webdav-report.json)。

| 检查 | Apache | Nextcloud |
| --- | --- | --- |
| 凭据错误报错、拒绝跨源、空工作区无设备头 | 通过 | 通过 |
| 8 客户端并发创建同一对象，内容不变；对象不被覆盖 | 通过 | 通过 |
| 4 台设备 × 6 轮并发编辑共享与各自文档，并行同步后收敛到同一提交 | 通过 | 通过 |
| 48 次编辑中未被设备有意替换的全部保留（原位或冲突副本） | 通过（42/42） | 通过（42/42） |
| 每台设备恰一个头且均指向收敛提交 | 通过 | 通过 |
| 设备头写入响应丢失（应答后 / 发送后断开），下一轮回读确定结果 | 通过 | 通过 |
| 另一安装复用同一 deviceId 被拒绝 | 通过 | 通过 |
| 其他设备头回滚或删除被识别为回滚 | 通过 | 通过 |
| 提交对象缺失或被篡改时拒绝应用 | 通过 | 通过 |
| 大对象上传中取消不推进头，下一轮完成 | 通过 | 通过 |
| `devices/` 中未知条目使同步停止 | 通过 | 通过 |

Apache 头写入在修改后 1 秒内只给弱 ETag，设备头因单写者允许回读后无条件写；Nextcloud 返回强 ETag 并在 PUT 响应中携带。本轮两个服务都未出现需要重试的 423/500。

## 4. 性能（回环，单次测量）

| 指标 | Apache | Nextcloud |
| --- | --- | --- |
| 1 MiB 上传 / 下载 | 51 / 19 ms | 248 / 206 ms |
| 4 设备并发同步单轮耗时 p50 / p95 | 432 / 600 ms | 25.9 / 40.7 s |
| 单轮请求数 p50 / p95 | 141 / 191 | 139 / 187 |

请求数主要来自每轮重新读取各提交及正文对象（测试设备每轮全量载入快照）。Nextcloud 单请求约 200 ms，单轮约 26 s，不适合日常使用。第 3 步需要：本地缓存已校验的提交与对象，按差异下载；合并时只读取到最低公共祖先为止。这些数据不能作为外部网络承诺。

## 5. 支持清单与遗留事项

冻结支持：Apache httpd 2.4.69 mod_dav_fs、Nextcloud 31.0.14，均为上表配置。其他服务在加入清单前必须通过 `pnpm verify:webdav`。

遗留到后续阶段：TLS 与原生凭据存储（第 3 步）；请求数与本地缓存优化（第 3 步）；同一文档双方编辑目前保存为冲突副本，行级三方合并与冲突界面（第 4 步）；历史检查点与远端回收（首发后单独验证）。
