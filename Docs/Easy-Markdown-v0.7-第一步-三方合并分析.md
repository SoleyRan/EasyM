# v0.7 第1步：三方合并分析

完成日期：2026-10-16。基线 `main` / `36b8163`，当前分支 `feature/v0.7`，实现与验证已提交为 `12d8b8f`，未推送。范围见 [冻结计划](Easy-Markdown-v0.7-设计与实施计划.md)。

## 使用方式

桌面打开已保存 Markdown，外部程序修改同一文件后切回 EasyM；在“文件已被外部修改”提示中点击“比较外部版本”，再点“分析三方合并”。

- 没有交叠修改时，显示只读“合并候选”，可以选择、复制；本地和磁盘各自的独立改动都包含在内。
- 有冲突时，显示共同祖先、本地片段和磁盘片段，以及基线行范围。不生成冲突标记，也不自动选择某一方。
- “收起三方合并分析”取消后台任务；关闭窗口保留原编辑，自动保存继续暂停。原有另存本地副本、显式加载磁盘版本和过期 revision 拒绝覆盖仍可用。

**本步不能应用候选。** 第二步才提供冲突选择、合并前持久保护、资源核对及带 revision 检查的安全提交。

## 实现与契约

共同祖先 B 来自当前标签的 `FileSnapshot.originalText`，且必须有对应的文件身份和 revision；本地 L 为内存正文，外部 R 为本轮磁盘检查的正文。成功打开、保存或重载才更新 B，不用历史中“相近版本”猜祖先。草稿没有可验证基线时回退双方比较。

`src/core/merge.ts` 独立实现逐行三方分析，复用既有有界 Myers 差异提取 B→L、B→R 的基线范围。非交叠区间组合，相同修改去重，连通交叠区间保留三方内容。同一行不同字符与删除边界插入保守地视为冲突；不尝试 Markdown 结构或图片的语义合并。保留空正文、空行、末尾换行、Unicode、围栏等字面内容；内部使用 LF，不据此决定最终编码/BOM/换行。

`src/platform/merge.ts` 使用现有差异 Worker，每次请求独立实例，关闭/输入变化时终止；10 秒超时、启动/发送/后台/消息错误返回明确的全文比较提示，过期回复不更新结果。每份输入最多 5 MiB / 100,000 行；两次差异共用 9.5 秒期限，各自轨迹上限 2,000,000 单元；最多 2,000 个改动区域，完整候选最多 10 MiB。显示最多 20 处冲突、每片段前 20,000 字符、候选前 200,000 字符，均有截断说明，双方原全文仍在下方。

分析不调用原生写接口，不改基线、撤销、草稿或图片资源。显示“无文本冲突”仅说明逐行文字能组合，图片、编码和换行仍须核对，不能据此直接写盘。
